# 剧情记忆

随应用交付的 Timeline 扩展。首次安装默认启用服务端与界面模块；既有的停用、卸载选择会保留。每个故事仍通过现有扩展管理选择是否采纳。

## 使用

1. 在 Agent 预设中打开「剧情总结」，选择模型。LV1 / LV2 共用一个预设，任务的 `summary.level` 条件分别启用对应 Markdown 条目。
2. 在当前故事的扩展管理中采纳「剧情记忆」，打开「记忆 → 剧情记忆」。
3. 默认每 32 楼形成固定范围，在后续正式正文输入时异步准备摘要。可以在工作台修订摘要，确认整批后，达到 8 楼原文缓冲边界才首次采用。
4. 已常驻的 LV1 达到 12 份或合计 12000 Token 时准备 LV2；确认时要求 LV2 的 Token 数少于其全部来源 LV1 的合计，再替代对应 LV1 的常驻注入。下层摘要继续保留供探索。

这些阈值及 LV1 / LV2 输出上限均可在工作台设置。关闭自动准备后仍可手动准备；停用扩展则退出其注入与工具视图。生成失败、超出输出上限或未确认的草稿不会替代已采用的记忆。模型未绑定时明确报错，不借用主写作模型。

## 数据与边界

- 批次、首次采用记录及策略均存于 Timeline Extension Record，随 Timeline 存档迁移。已确认批次不可修改；每次生成或修订使用临时任务 Session，保存结果并确认领取后软删除；修订显式携带原始来源、当前草稿与修订要求。宿主保留尚未领取的任务结果，保存失败后可在修订时恢复；显式丢弃会先释放遗留任务，释放失败仍保留批次供重试，带遗留任务的批次需要在其创建分支丢弃。剧情提交变化会重新校验并取消来源已失效的运行任务。
- LV1 绑定原文节点与内容摘要；LV2 绑定有序 LV1 ID 和版本。有效性取决于当前剧情路径，后段 Swipe 不撤销来源仍有效的已采用摘要；改写或退回来源范围内则不再注入。
- `/story-memory/index.md` 提供索引，`LV1/起楼-尾楼.md` 与 `LV2/起楼-尾楼.md` 提供只读探索视图。LV2 附直接 LV1 来源链接；原始正文仍由 Narrative 保存与读取。
- 专用 Agent task 使用隔离上下文，接收指定来源、总结预设、自身修订历史，以及预设允许的角色世界书参考，避免隐式带入整段主写作上下文。不会写入共享 `MEMORY.md` 或 Session 交接摘要。
- 存档保留摘要及其来源关系，不恢复运行中的任务。导入后未完成任务可重新生成。

`server.js` 可直接加载；界面源码位于 `ui/`，使用官方 `@loom-studio/ui` 基础控件，执行 `pnpm --filter @loom-studio/story-memory build` 生成 `client.js`（React、React DOM 与官方 UI 由宿主共享；Shadow DOM 的官方控件样式由宿主挂载）。`pnpm build:app` 已包含此步骤。库构建不复制仓库 `public`；正式发布只复制 manifest、package.json、正式图标、client.js、server.js、resources 与 README，不携带界面源码、构建脚本、草稿或开发用 `node_modules`。`resources/summary/index.json` 加 `entries/*.md` 是预设源文件；宿主只提供通用存储、任务、上下文、VFS、存档和 `memory.panel` 插槽。

角色世界书通过预设中的 `@lore.stable` / `@lore.lower` 定位，默认开启 `useCardLore`，不默认绑定全局世界书。世界书帮助理解背景，不作为本批事件发生的证据。

剧情总结预设默认关闭 `useGlobalLore`，只继承角色世界书；普通预设默认继承用户已挂载到全局的世界书。全局继承关闭不影响用户为该预设显式添加的 Lore。

手动「立即总结 LV1」不受自动触发阈值限制：从未总结的下一楼开始，最多读取一批，当前只有 1～3 楼也能生成。手动压缩 LV2 只要求至少两份连续、未升层的常驻 LV1，不要求达到数量/Token 阈值。手动生成仍需确认，并沿用首次采用的原文缓冲设置。
