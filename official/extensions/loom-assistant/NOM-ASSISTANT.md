# 诺姆助手：头像、表情与包内资源设想

记录日期：2026-10-26。状态：产品设想与后续验证清单，尚未实施；不代表资源引用协议或独立仓库方案已经确定。

## 目标

让官方问答预设逐步承接 Website 看板娘 Nom（诺姆）的形象与人设：拥有头像，并能在合适的回复中引用随扩展提供的表情。例如完成一项工作后，正常说明结果，再附一张庆祝或点赞表情。表情是辅助表达，不代替结果、错误或需要用户决策的信息，也不要求每条消息都附图。

以此验证完整使用链路：扩展携带图片资源 → 预设 Agent 了解可用资源 → 选择并引用表情 → 会话渲染 → 重载后仍可查看。

## 已确认的现状与素材来源

- 本扩展 ID 为 `official.loom-assistant`，预设贡献 ID 为 `official.loom-assistant.preset`。当前 manifest 显示名称为 `Loom Assistant`，预设仍是通用 Loom Studio 问答助手，尚未接入 Nom 头像和表情。
- 当前预设在 `resources/assistant-preset.json`；知识资源在 `resources/knowledge-lore.json`。现有脚本及文本资源验证应继续保留，角色化不应改变它们的职责。
- 相邻 `LoomStudio-website` 仓库已有 Nom 图片。`src/data/nom-stickers.json` 提供表情 ID、文件路径、用途及示例文字；实际贴纸位于 `public/images/nom/stickers/`，包括全身 8 张、胸像 25 张。
- 可优先考察 `bust/smile.png` 作为头像候选，`bust/thumbs-up.png`、`fullbody/celebrating.png` 作为完成反馈，`bust/thinking.png` 作为思考表达。头像是否裁切、最终使用哪一张，留待视觉确认。
- Website 的 `README.md`、`docs/plans/nom-stickers.md` 和 `public/images/README.md` 记录素材组织与使用背景。Website 已有形象和人设是本次用户提出的复用方向；正式人设文本的权威来源及移植范围仍需后续定位确认，不能只凭表情文案补写成既定设定。

以上路径相对于各自仓库，不把开发机绝对路径写入扩展运行资源。

## 建议的最小落地顺序

1. 整理既有人设与素材来源，确定一个头像、少量常用表情及稳定的资源清单；先复用现有素材，不重新生成整套角色。
2. 调研宿主已有的包内静态资源访问、预设头像、消息图片及附件引用能力，区分扩展列表图标、Agent 头像与消息表情三个用途。优先走现有契约，不能因 manifest 的 `icon` 可用就认定消息图片也已支持。
3. 给预设提供简短的表情目录（语义 ID、含义、适用场景），由 Agent 按上下文选择。资源定位交给宿主可解析的引用，不让模型猜本机路径或依赖 Website 在线热链；不把整套图片或 base64 塞进提示词。
4. 打通一个真实闭环：完成工作 → 文字结果附一张包内表情 → 会话重载后正确展示。具体采用 Markdown 图片、结构化附件还是现有资源引用机制，依据调研结果决定，此文不预设新协议。
5. 闭环通过后再扩充表情与角色表达，并验证包升级、停用、卸载后的历史消息行为。

## 独立追踪与分发

用户倾向于未来单独追踪诺姆助手，因为它将包含持续增长的表情与角色资源。可将它作为独立扩展仓库维护预设、人设、头像、资源清单和发布版本；当前仅记录方向，不创建仓库、不迁移 Git 历史、不改现有加载路径。

独立分发前需确定素材的唯一维护来源、Website 与扩展间的同步方式及素材授权说明，避免两边各自修改同名文件。先选择少量图片随包发布；是否需要额外的素材仓库或大文件方案，应由实际包体与更新成本决定。

## 后续验收与待决策项

- 安装后的独立包能访问头像与表情，不依赖相邻 Website 检出目录、开发机路径或官网在线服务。
- Agent 只引用清单内真实存在的资源；不存在的引用应有明确可理解的反馈，不能伪装成已发送图片。
- 回复中保留文字结果、图片替代描述和合理尺寸；浅深主题、窄屏与历史记录重载均可读。
- 确认历史消息应保存资源快照还是依赖包版本，并明确升级、停用、卸载后的行为。这涉及资源持久化契约，实施前单独决定。
- 明确表情开关与频率是否需要用户设置；初版优先少量、上下文相关的表达，不默认建设复杂情绪系统。
- 完成以上真实链路验证后，才可宣称扩展携带资源与预设 Agent 使用资源已得到验证。本文本身不构成实现或验证结果。

## 2026-10-26：预设图标已接线

扩展图标使用从 Website `public/images/nom/stickers/bust/smile.png` 复制的 `icon.png`。预设资源与官方初始预设均声明：

```json
{
  "metadata": {
    "icon": {
      "kind": "package",
      "packageId": "official.loom-assistant",
      "path": "icon.png"
    }
  }
}
```

`path` 相对扩展包根目录；`packageId` 明确所属包，使复制的预设不依赖自身 origin。包内安装时，同包引用会补上实际安装 target（全局或角色）；个人复制和 JSON 导出保留引用，图片本身仍由安装的扩展提供，不承诺脱离扩展的独立图片分发。宿主通过现有包文件接口读取当前可用版本，不把本机路径或带版本 URL 写入声明。

已接入预设库条目与创建会话时的预设选择。来源分组继续显示扩展图标。现有官方初始预设在服务启动同步时更新；扩展贡献预设通过扩展资源更新流程同步。历史消息头像与 Agent 发表情仍属于前文设想，本次未实现。
