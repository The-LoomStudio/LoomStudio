# 国际化指南 (i18n)

Loom Studio Client 支持 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`，中文是词条键的基准与最终回退。
当前使用类型化字典和 `createTranslator(locale)`，不依赖 Context 或翻译 Hook。词条替换只支持 `{{name}}`，不提供 ICU 或复数规则；日期和数字使用同目录 `format.ts` 中基于原生 `Intl` 的 `formatDateTime`、`formatDate`、`formatTime`、`formatNumber`，不要在组件中另写格式化器。

## 文件位置

所有的词条字典存放在：

- `apps/studio-client/src/shared/i18n/zh-cn/*.ts`
- `apps/studio-client/src/shared/i18n/en-us/*.ts`
- `apps/studio-client/src/shared/i18n/ja-jp/*.ts`
- `apps/studio-client/src/shared/i18n/ko-kr/*.ts`

每种语言按业务域组织，包括 `common`、`sessions`、`agent`、`resources`、`characters`、`state`、`prompt`、`extensions`、`settings`、`textTransforms`、`logs`、`observation`、`user-profile`、`notifications`、`search`。同级 `zh-cn.ts`、`en-us.ts`、`ja-jp.ts`、`ko-kr.ts` 是聚合出口；这是源码拆分，不引入运行时命名空间或异步加载。

新增词条优先放入已有业务域。新增独立业务域时，四种语言都要增加同名文件，并在各自聚合出口导入和展开，不按单个组件继续细拆。

## 开发规范

### 1. 以中文为第一公民

新增词条同步补齐四种语言，参数名保持一致。其他语言聚合出口通过 `satisfies Record<keyof typeof zhCN, string>` 校验中文键合同。不要留下空译文：运行时的空值回退不会把空字符串替换为中文。

### 2. 避免在 UI 代码中硬编码中文字符

> 唯一允许硬编码中文的例外情况是：高度临时性的 PoC（概念验证）页面，或者只有极少数特定人群会看到的 debug 内部面板。
> 在任何面向用户的正式组件中，使用当前语言的 `Translator`，包括按钮、提示、错误说明和可访问名称。用户正文、协议字段、原始日志不强行翻译。

沿现有组件的 `t: Translator` 属性向下传递，不另建 Context 或 Hook。语言所有者调用 `createTranslator(locale)`；模块级 `t()` 固定使用中文，不适用于需要响应语言切换的组件。

```tsx
import type { Translator } from '@/shared/i18n'

export function TimelineLabel({ t, name }: { t: Translator; name: string }) {
  return <span>{t('sessions.selectTimelineNamed', { name })}</span>
}
```

### 3. Key 的命名

使用按所属功能块区分的扁平点分字符串，例如 `sessions.selectTimelineNamed`，不是嵌套对象。移动文件不改变键名或调用方式。
请不要过度复用那些在不同语境下可能有不同翻译的单词（如不要全系统只用一个 `open`，它可能是“打开”也可能是“开放”）。

## 最小检查

```sh
pnpm exec vitest run tests/unit/client/i18n.test.ts
```

检查业务域与键集合一致性、同文件及跨文件重复键、空译文、插值参数一致性、聚合出口完整性及现有翻译行为。涉及键或公共类型变化时，再执行 Client 类型检查。

字典组织完成不代表全量界面已完成国际化。日期/数字沿用现有原生格式化入口；复杂复数和扩展自有翻译合同仍需独立确认；确实需要复杂消息语义时再评估成熟翻译引擎，不在当前替换器上自建规则。
