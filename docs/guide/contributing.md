# 参与贡献指南 (Contributing)

如果你想要为 Loom Studio 贡献代码、修复问题或改进文档，这里是你应该了解的全部流程。

## 1. 建立开发环境

首先，你需要将项目克隆到本地，并跑通开发环境。
👉 **[第一步: 阅读《快速启动指南》](getting-started.md)**

## 2. 熟悉项目结构

在你准备修改任何一行代码前，为了避免打破系统的分层架构，你必须了解项目的目录结构和各个 package 的职责划分。
👉 **[第二步: 仔细阅读《项目全量文件地图》](project-structure.md)**
你也可以参考 [Package 依赖图](../reference/dependency-graph.md)。

## 3. 认领任务与设计

对于微小的修复或文案修改，你可以直接提交。
但如果涉及架构改动、新增 API 或大幅度的功能引入，你需要：
1. 确认这不是内核层的禁区（内核 `kernel` 不做业务）。
2. 在 `workbench/discussion/` 或 `workbench/adr/` 提出你的设计草案，并进行讨论。

## 4. 编写代码的规范约束

- 你的代码风格必须符合我们的约定：👉 **[代码与命名规范](code-style.md)**
- 你的 UI 代码如果涉及界面调整：👉 **[UI 设计与 CSS 架构准则](ui-design.md)**
- 所有向用户可见的新文案必须：👉 **[符合国际化流程](i18n.md)**

## 5. 测试与验证

我们极其看重代码带来的稳定性，并且拒绝伪装成回归测试的冗余历史包袱测试。
- 在你提交代码前，确保你理解了应当在哪里补充测试：👉 **[测试准则](testing.md)**
- 运行 `pnpm test` 确保没有破坏现有流程。

## 6. 提交 PR (Pull Request)

当你准备好合并代码时：
- 整理你的 commit 记录，采用语义化格式（如 `feat(runtime): ...`）。
- 确保你的 PR 能够通过 CI 检查。
- Reviewer 将会严格按照我们的架构红线审查你的代码：👉 **[审查检查点边界](code-review.md)**
