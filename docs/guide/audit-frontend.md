# 前端审计方向

供 React Client 审计和 Bug 排查按需选读，流程、证据与输出要求见[审计入口](audit-workflow.md)。以下是检查问题，不表示当前代码存在这些缺陷，也不要求每轮扫描全部方向。

从 [Client README](../../apps/studio-client/README.md)定位当前 feature、widget、shared 和验证入口；能力选择参考[依赖所有权](../architecture/platform/external-dependency-ownership.md)，样式参考 [UI 准则](ui-design.md)。源码入口和领域行为以当前文件为准，不凭本文恢复旧组件或旧状态模型。

## 1. UI 结构与 SCSS 收敛

**检查什么：**

- 创建/编辑、详情/列表是否重复维护同一业务语义的表单、字段校验、提交与错误恢复；先判断共同演进关系，再考虑合并。
- 是否重复实现 Card、Dialog、工具栏、标题分割、加载/空/错误状态等已有 UI 能力。
- SVG、选项、格式化文案是否存在同一所有者的重复定义；不同语言、不同业务合同的相似文本不强行统一。
- SCSS Modules 中是否有孤立选择器、重复 keyframes、重复主题值，或已无生产者的状态 class；检查全部导入者、跨目录消费、动态 class、全局祖先和主题扩展。
- 魔法尺寸是否承担真实布局或测量合同；同义设计值才收敛为现有 CSS 变量，不能把所有数字配置化。

**避免误改：** 第一方 UI 使用 SCSS Modules 与 CSS Custom Properties，不照搬 Tailwind 长类名扫描，不要求引入 `cva`。组件结构相似不证明应该合并；若需要大量模式参数和条件分支，优先只共享稳定的机制或保留独立组件。删除样式时不能误删混合选择器中仍活跃的分支、焦点状态、窄屏与减少动态效果支持。

**最小证据：** 真实挂载入口、Props 消费方、样式全部消费者，以及删除后保留的交互。局部静态改动核对 Diff；涉及样式编译或导入边界时再选择构建检查。视觉效果由用户验收，不以构建代替。

## 2. 状态权威、草稿与查询缓存

**检查什么：**

- `useState + useEffect` 是否只复制 Props 或另一份状态；可以直接计算时删除双写，不默认再套 `useMemo`。
- 区分服务端快照、编辑草稿、提交版本基线、乐观结果和展示投影；确认每份状态的创建、失效与恢复职责。
- 是否绕过现有 Query 能力重复维护缓存、loading/error、分页、重试或订阅；Zustand 是否无必要地复制远端权威数据。
- 查询键是否覆盖实际数据身份和范围；事件失效是否准确携带 scope/operation，是否误刷其他对象或漏刷新。
- 保存冲突、外部更新、删除和网络失败后，草稿是否可保留或恢复；刷新失败是否误清草稿或诱导重复提交。

**避免误改：** 编辑草稿和服务端快照并不冗余；后台刷新期间保留旧数据和错误可能是有效状态。不能仅凭多个布尔值就重建状态机，也不能把所有状态都迁到同一个 Store。

**最小证据：** 写入点、读取点、身份键、版本基线与失效规则。以实际 Hook/QueryClient 的受控交错或已有用例核对主要风险，不用替代核心逻辑的 mock 证明行为。

## 3. 异步交错与生命周期

**检查什么：**

- 快速切换 Card、Timeline、Branch、Session、资源或 API endpoint 时，旧请求结果是否写入新目标。
- 连续保存、搜索和分页是否发生逆序覆盖；闭包读到的身份、版本、配置是否属于请求发起时或当前时的正确一方。
- 组件关闭或卸载后，监听、Observer、计时器、Object URL 和订阅是否由正确所有者释放；共享任务是否被一个消费者误取消。
- 取消 UI 观察、取消后台执行和撤销已提交写入是否被混淆。
- mutation 已提交但辅助刷新失败时，成功状态、重试入口与错误提示是否仍准确。

**避免误改：** 不给所有异步函数机械添加 AbortController 或 mounted flag；先确认哪个结果应被拒收、哪个执行需要继续。卸载后的回调本身不证明内存泄漏，需定位仍被保留的资源及生命周期。不能吞异常来消除警告。

**最小证据：** 写清 A 发起 → 切换 B → B 完成 → A 晚到等具体时序，观察身份、数据与提示是否一致；不要只搜索 Effect 依赖数组。

## 4. 流式展示、虚拟列表与阅读位置

**检查什么：**

- 当前增量、持久历史与最终正文采用是否正确交接；重连与刷新会不会重复追加、丢片段或用旧历史覆盖实时文本。
- 行身份是否独立于数组位置，编辑和候选切换是否保留正确归属；虚拟列表是否保活正在编辑的内容。
- 外层跟随、虚拟器末端锚定、工具详情滚动是否重复争夺控制；用户上翻、选择文字、聚焦和锚点跳转是否暂停对应跟随。
- 向前加载、动态测高、iframe 延迟高度、折叠展开和恢复阅读位置是否使用正确对象范围与稳定锚点。
- Run 完成、失败、暂停、取消和观察断连的显示是否对应真实事实，是否捏造工具结果或提前显示成功。

**避免误改：** 不把展示缓冲、canonical 记录和恢复数据视为同一状态；不能为减少状态而取消必要的测量、阅读保留或恢复过程。Narrative 与 Session 的关系按[当前运行时合同](../architecture/application/agent/runtime-and-session.md)核对，不套用旧双流模型。

**最小证据：** 投影逻辑可用定向用例；滚动、测量、焦点和实际 DOM 身份需要相应浏览器证据。SSR、静态源码断言和截图不证明完整交互。

## 5. 内容渲染、交互与信任边界

**检查什么：**

- Markdown、HTML、链接和扩展 Renderer 分别经过什么清洗、URL 策略与执行边界；不要把允许的作者脚本与普通文本渲染混为一谈。
- iframe 消息来源、目标实例、卸载后回调和权限是否正确；主题更新、重载与销毁是否泄漏订阅。
- 日志、复制、错误详情和前端资源中是否意外包含凭据或不该暴露的正文；报告保留证据但不复制秘密值。
- Dialog、菜单与异步反馈是否保留语义、键盘操作、Escape、焦点恢复和错误可达性。

**避免误改：** `dangerouslySetInnerHTML` 只是追踪入口，不单独构成漏洞；先看实际来源、清洗和宿主合同。复用现有 parser、sanitizer、菜单和 Dialog，不叠加另一套处理链。脚本能力变化属于产品与权限边界，不能在样式精简中顺手关闭。

**最小证据：** 输入 → 转换 → 渲染/执行端的完整链，以及能穿过当前防线的样本或明确反证。按 [iframe 合同](../architecture/ui/iframe-runtime.md)与 [Renderer Host](../architecture/extensions/client-renderer-host.md)选择验证。

## 6. 性能、包体积与模块边界

**检查什么：**

- 高频流式状态、输入和全量 Store 订阅是否影响无关重型消费者；先确认实际渲染和订阅成本。
- 是否为单个可见消费者读取、解析或转换全量历史；转换顺序和 Display 语义是否允许缩小输入。
- 无界集合、缓存、DOM、Object URL、Worker 或 Renderer 实例是否持续增长，有无清晰释放点。
- 重型编辑器、渲染器和计算是否进入不需要它们的首屏路径；按实际 bundle 和调用入口判断懒加载价值。
- widget 是否承担领域编排，shared 是否反向依赖业务层，App facade 是否继续拥有各领域状态与命令。

**避免误改：** 普通循环、内联对象和匿名函数不是性能缺陷；不机械增加 memoization、Worker 或虚拟化。先确认现有依赖、编译行为与收益。shared 代码进入浏览器后不能因类型检查通过就假定 Node-only 依赖可用。

**最小证据：** 指明消费者、数据规模、测量指标和对照条件；没有实测时标为候选。改变跨包类型或打包边界才选择对应检查，不把微基准收益冒称整页体验改善。

## 跨端交接时带走什么

向[后端专项](audit-backend.md)交接实际 RPC/事件入口、请求身份与版本、返回值/错误、前端预期与观察结果。至少确认写入是否已提交、事件代表什么、重试是否可能重复副作用；不要用“后端大概会保证”结束前端审查。
