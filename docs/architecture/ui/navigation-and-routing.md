# Navigation and Routing

Loom Studio 将应用内导航、资源身份和外部入口分开：导航负责去哪里，资源 URI 负责目标是谁，URL 负责从应用外进入。普通面板操作不再用 Path 替换 Timeline 上下文。

## 状态归属

### URL 与 URI

`/` 和 `/studio` 为统一入口。可分享的实体链接使用 `/studio?target=<编码后的 loom-resource URI>`，正文快照引用仍沿用原有带版本、行范围的引用查看器，不伪装成编辑目标。

现有显式 `/studio/chat/...`、资源和 Panel 路径仍可作为入口，接收后统一解析并 Replace 到 `/studio`。入口列表和 Panel 路径集中定义，不再维护互相遗漏的两份表。

### History State

浏览器 History State 保存当前位置，包括 Timeline、Branch、Panel、选中资源、显式节点和查看条件。面板切换与资源选择 Push 到同一个 `/studio` URL；返回/前进恢复该位置。关闭面板只清理面板定位，不清空当前 Timeline/Branch。

面板局部搜索输入和筛选 Replace 当前位置，不逐字创建历史。[全局资源搜索](../application/global-resource-search.md)的关键词、范围和类型由独立的 endpoint 级 Zustand 持久状态保存；打开结果才调用既有导航。编辑正文、Hover、拖动尺寸、手风琴与普通滚动不进入导航历史，编辑撤销仍归编辑器负责。

### 工作区恢复

最后工作区位置按 API endpoint 保存在本地；不保存业务正文、凭据或待解析的外部目标。布局和编辑状态仍使用各自已有所有者。

`cardId` 只标识角色包浏览目标，`previewCardId` 标识尚未创建故事的游玩预览。明确预览会写入后者，返回/刷新恢复实际预览角色；普通浏览不会改变它。已创建故事的角色由 Timeline 来源决定。旧记录未区分两种身份时不猜测转换为预览。

普通故事选择先发布导航目标，由 App 的恢复入口加载领域对象；异步发布还须确认目标仍有效。最新明确目标选择覆盖旧请求；打开设置等临时工具不取消底层加载，完成或失败也不关闭后来打开的工具。返回/取消旧目标阻止其发布；“返回正文”使用最近完成的故事/预览位置。搜索资源在请求前登记选择顺序，不能按响应先后决定最终选择。

优先级为：显式深链 > 当前标签页有效 History State > 上次持久化工作区 > 默认界面。基础数据就绪后再加载恢复目标；不存在的 Timeline/Branch 显示不可用，不切换到其他分支。启动恢复不是业务数据恢复，也不是浏览器历史的跨重启完整存档。

### Zustand

Zustand 保存 Panel 与目录宽高、文件树展开状态、当前 Asset、编辑器偏好和其他本机布局选择。普通目录节点点击保留局部编辑器选择；明确的资源选择与引用跳转进入导航。Shell 直接消费导航的当前 Panel，不维护第二份 Panel Store 投影。保活面板仅在其 Shell 宿主与内部 Tab 都活动时注册全局工作台返回处理器。

## 定位示例

```text
普通启动：/studio
资源身份：loom-resource://entity?type=resource&id=<resource-id>
资源节点：loom-resource://entity?type=resource&id=<resource-id>&nodeId=<node-id>
剧情节点：loom-resource://entity?type=timeline&id=<timeline-id>&branchId=<branch-id>&nodeId=<node-id>
外部链接：/studio?target=<URLSearchParams 编码的资源 URI>
```

URI 按 ID 解析，不按名称或文件路径猜测替代对象。资源链接不会把资源内容传给其他实例，也不会绕过访问权限。Session 引用先校验目标，再打开历史浮层中的会话摘要；Provider 引用打开模型管理并携带 `providerProfileId`。Run 引用打开应用日志筛选，不代表完整运行快照。解析入口为 `shared/studio-shell/studio-target.ts`。

## History 规则

- 从 Chat 打开或切换 Panel、选择独立资源：同 URL Push；
- 普通 Asset 节点选择：局部状态；明确的节点引用通过导航定位；
- 外部 URI：解析后 Replace 入口，不留下临时解析页；
- 搜索和筛选：Replace；
- Hover Sidebar、拖动尺寸和展开目录：不写 History。

## 可引用资源

引用查看器由导航传入 URI 和回调，不自行修改地址栏。复制资源/消息链接生成统一入口 URL，不改变当前工作区。正文快照引用打开编辑器时转为明确资源位置，不把历史行号当成当前版本精确位置。

已访问的面板宿主关闭后隐藏，避免普通切换卸载编辑器；不等于所有面板都启动加载，也不等于隐藏组件不需要管理订阅与异步请求。

### 资源浏览与消费配置

角色列表点击只浏览角色包，不切换当前游玩角色；进入游玩是独立动作。包视图中的复杂 Lore / Preset 资源跳到对应专用面板，脚本与附件仍可在包内查看。外部单项资源通过现有临时打开逻辑按原 ID 编辑，未挂载不等于只读；打开不增加安装、挂载、复制或持久工作区成员。Header 返回恢复原查看位置，不另加“回原视图”按钮。

Agent Preset 配置详情以 Lore、正则 / 提取器、工具三个子 Tab 展示来源 FileTree，复用搜索、折叠和图标开关。点击 Lore 或规则行打开定义编辑，开关修改的是预设消费配置，不是原定义的全局启用。启用资源图标高亮、停用行弱化；目录不提供 Lore 上下移按钮，但不改变现有保存顺序合同。

当前角色绑定的 Lore 分组置顶，资源用星号标记。`useCardLore` 草稿开启时标记“随角色默认采用”，由角色世界书总开关控制，不为显示状态创建额外 Mount；关闭后仍可显式采用。这个状态不表示关键词或 Activation 已触发。工具保留按行展开说明；Anchor / Session / Narrative 的复杂内容放在 Detail，而非目录内实时铺开，静态声明与运行检查结果分开。

### Header 故事快捷操作

Header 中央角色胶囊点击角色身份打开当前故事来源角色的面板；尚未开局时使用当前预览角色。独立箭头展开当前 Timeline 的重命名、新建、分支切换、从分支末尾创建分支与删除入口。新开故事使用胶囊对应角色，不使用资源面板正在浏览的角色。生成、暂停恢复和进行中的写入期间禁用故事操作。

删除角色复用角色面板的确认组件与删除范围预览，显示角色名，保留游玩数据和提示词资源选项；删除后清理相关导航。删除故事沿用既有 Timeline 删除与导航恢复。展示组件位于 `widgets/timeline-quick-actions/`，跨领域操作和导航由 `app/studio-timeline-actions.tsx` 组合。开发预览仅操作内存样例，正式入口不依赖预览模块。

### Agent 会话选择

Agent Chat 的会话选择由独立 `AgentSessionPicker` 承载：顶部名称输入框编辑当前会话，选择按钮打开搜索弹窗，按会话名称或预设名称筛选。弹窗可重命名会话，并通过星号独立指定主写作接收方；打开会话只切换查看目标，不顺带设为主写作。只有绑定当前 Timeline 的会话可被指定为主接收方，运行 / 暂停切换检查沿用 Runtime。

新建对话弹窗按名称或来源搜索预设，显式选择后创建固定绑定的 Session，可选择是否设为主写作，不使用原生下拉框。重命名失败保留输入，创建或指定主写作失败保留弹窗并报告错误；这些操作不改变预设资源定义。

## 托管要求

Studio 使用 Browser Router。开发服务器和正式桌面宿主必须将未知 `/studio/*` 路径回退到客户端 `index.html`，再由前端 Router 完成匹配。未匹配的应用路由保留原 URL 并显示统一 404 状态页，由用户明确返回聊天。

## 名称与辨识信息

Studio 在 `shared/api/studio-api.ts` 的 Timeline / Agent Session 创建入口为未提供 title 的记录生成简短默认名：本地化的“故事／会话”加月日、小时和分钟。名称使用当前界面语言与浏览器本地时间，生成一次后交给既有服务端 title 字段保存。同一分钟允许同名；辅助日期保留年份。显式名称、导入、历史数据和重命名不应用默认生成，直接调用 Runtime 的外部调用者保留原默认行为。

角色、预设和所属故事按现有 ID 从当前列表数据关联展示，不复制进 title，不增加查询或关联信息快照。Timeline 快捷菜单、Agent Session 选择器、历史和最近游玩列表复用这些信息；角色内列表省略重复角色，历史树子项沿用父行角色与故事。无 Timeline 的 Session 标识独立，失效关联标识不可用；已有正文预览可用于辨识，不批量读取完整正文。关联对象改名只更新辅助信息，不重写记录名称。

## File Tree 多选与批量操作

File Tree 在业务提供 `getBatchActions` 时启用多选，选择集合与当前打开的 `selectedId` 分开保存。Ctrl / Cmd 点击增减单项，Shift 点击或 Shift 方向键选择可见范围，按住修饰键与鼠标划过连续选择；从已选项起手连续取消。Ctrl / Cmd + A 只选当前展开、筛选后的可选行，Esc 清空。拖动手柄继续负责排序，输入框及行内按钮不启动划选。

松开鼠标后保留选区并自动显示已选数量与操作条；跨行拖选结束时的容器 click 不清空选区。右键已选项复用同一组批量动作，菜单打开期间隐藏操作条，关闭后恢复；右键未选项保留单项操作。删除先确认，写入期间阻止该列表再次操作；部分失败保留失败项选择和错误信息。虚拟滚动通过可见逻辑顺序计算范围，不依赖所有行同时存在于 DOM。

当前消费者为资源 / 预设正文目录、预设 Lore / 工具 / 正则使用配置，以及正则 / 提取器管理。只读和运行时投影不参与；角色默认继承的 Lore 由总开关控制。正文目录启停沿用实际资源写入，正则管理逐项携带现有版本写入并最终刷新；预设 Lore 和工具整体替换绑定，正则使用配置修改草稿并沿用保存按钮。移除绑定或恢复默认不会删除资源定义。普通 Settings 表单不作为多选列表。


## 工具工作台浮层（2026-10-20）

模型服务、设置和扩展管理使用居中的 `Dialog layout="workbench"`。History State 中的 `tool: 'model' | 'settings' | 'extensions'` 与底下 `panel` 独立；打开、关闭工具不清除工作面板的资源目标、搜索或 Timeline 上下文。工具及 `toolSearch` 不写入跨启动恢复位置，浏览器当前 History 仍可恢复它们。旧 `/studio/models`、`/studio/settings`、`/studio/extensions` 深链及旧工具面板位置归一化为浮层，显式深链优先复用该 endpoint 的可用工作现场。

工具查询参数与底下工作面板分开，扩展 `packageId` 由 `toolSearch` 提供。三个工具内容首次打开后保留挂载。设置与扩展内部 Master–Detail 使用 `navigationScope="local"`，窄屏返回列表不注册或清除底下工作区的返回控制。

扩展管理与实际工作界面分别呈现。显式打开 `shell.workspace-panel` 贡献后，关闭管理浮层并进入工作区；该位置由 `panel: 'extensions', extensionWorkspace: true` 标识，防止恢复时误当作旧扩展管理入口。工作界面的返回操作释放当前 Surface 并重新打开管理浮层。从管理进入资源编辑或日志同样退出工具浮层；`standalone.page` 保留既有独立会话窗口。

安装、更新、卸载等嵌套确认继续使用普通 Dialog；原生 Top Layer 管理层级，关闭事件不向父层传播。网络保存与扩展操作的错误原位展示，不依赖浮层背后的全局 Toast。


### 历史工具与游玩入口

Dock 的“历史”沿用内部 `recent` 身份，属于工具浮层；内容分为“最近 / 剧情 / 会话”，由 `toolSearch.historyTab` 保存当前页。最近复用原最近展示；剧情与会话复用原历史管理，默认只显示当前角色卡的剧情及其关联会话；点击“显示全部”后才包含其他角色与独立会话。剧情详情可查看关联 Session。

游玩直接显示角色入口，已移除角色/历史子 Tab 和旧 playTab 布局偏好。`/studio/history` 打开历史浮层，旧 sessions 存储位置迁入剧情页；旧 `/studio/play?sessionId=...` 及摘要入口进入历史会话页。查看详情、摘要、重命名与批量管理留在浮层，显式打开故事或会话后关闭浮层。切换角色的已有剧情或角色预览时，保留底下已打开的工作区面板、资源选中项和搜索条件。工具参数不改变底下资源目标或搜索。

历史的原生 Dialog 内，ContextMenu / DropdownMenu 通过 UI 包的 DialogPortalContext 挂入最近的所属 Dialog，并以它为碰撞边界，避免落入模态层外的 inert 页面。普通页面菜单继续沿用默认 Portal；嵌套 Dialog 拥有自己的菜单宿主。

### Agent Preset 模型选择

预设模型入口使用可搜索的 Dialog，按提供商账号分组。当前绑定独立显示；已添加模型可直接绑定，账号目录由用户按需获取或刷新，搜索框也支持输入精确模型 ID 手动添加。读取目录不写入账号；选择未添加的模型时，先添加到账号，再保存预设绑定。保存成功关闭弹窗；失败保留当前绑定并原位提示，部分成功时说明模型已添加但预设未保存。账号模型启用规则与现有持久化合同保持不变。
