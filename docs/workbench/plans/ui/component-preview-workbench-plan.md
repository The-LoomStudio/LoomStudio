# 开发环境组件预览入口

> **Status**：入口与样例已实现 / 验证记录待收口
> **2026-09-12 核对**：开发入口已落地；下文工作包保留验收要求，不再作为从零建设的待办。此次状态核对不补认生产构建或浏览器验收通过。

## 目标

在现有 Studio Client 内提供开发专用预览入口，让主 Agent 用真实组件和样例数据确定 UI 设计。用户确认后，业务实施者为同一组件接入正式数据，避免从截图二次还原。

长期流程见 [UI 开发准则](../../../guide/ui-design.md)，本 Plan 只记录入口建设范围。

## 已确认事实

- [Client 入口](../../../../apps/studio-client/src/main.tsx) 在 `import.meta.env.DEV` 分支内识别预览路径并动态加载预览宿主；普通入口才执行 `POST /auth/session` 后挂载 App。
- [Client README](../../../../apps/studio-client/README.md) 定义当前启动方式、分层和数据流，预览应复用其 React/Vite、主题与基础控件。
- 已有 [MasterDetailWorkbench](../../../../apps/studio-client/src/shared/ui/master-detail-workbench/master-detail-workbench.tsx) 和 [AssetWorkbenchLayout](../../../../apps/studio-client/src/shared/ui/asset-workbench-layout/asset-workbench-layout.tsx)，不需要另建分栏与下钻体系。
- 当前工作区还有其他 UI 与文本管线修改；实施前核对入口现状，不覆盖并行变更。

## 决策

1. 复用已存在的 `/dev/preview/:previewId` 开发入口；当前注册 `text-pipeline` 与 `card-resources`，不另建平行宿主。
2. 用显式组件注册表将稳定 ID 映射到本地组件和样例；未知 ID 显示预览未找到，不任意解析模块路径，不执行用户代码。
3. 开发预览在正常认证启动前分流，只挂载所需展示环境，不初始化业务 App、RPC、事件连接或持久布局 Store；普通页面仍按原认证链启动。
4. 生产环境不注册预览路由或导航，预览样例代码不进入生产产物；不得仅靠隐藏链接实现。
5. 主 Agent 制作代表性组件草稿，业务实施者接入真实功能；展示组件放在现有领域层，预览只提供样例 Props 和本地交互。
6. 宿主按实际需要选择控件限宽、Panel 填充或最小浮层场景，复用主题和基础布局，不先实现通用宿主配置 DSL。
7. 首个样例应有列表、单项详情和窄屏下钻，可切换正常、空列表与较多内容；不在本计划中重做 State 或 Extension 产品设计。

## 非目标

- Storybook 等新依赖、组件市场、通用设计系统或自动截图平台。
- 后端、数据库、权限或正式应用路由的业务语义变更。
- 为所有现有面板补样例，或顺手重构其业务状态。
- 新增代码执行平台、任意文件加载、持久 Mock Store。
- 以自动化替代用户视觉确认。

## 工作包与文件边界

### A. 开发入口与最小宿主

主 Agent 保留启动隔离设计与入口关键接线，避免将认证边界交给子代理后再完整重审。

- 允许范围：`apps/studio-client/src/main.tsx`、新建 `apps/studio-client/src/dev/preview/`。
- 复用现有主题与布局；不修改 Server、真实业务 Store 或共享布局合同。
- 完成条件：开发预览可直接打开，不依赖后端，不触发认证或业务连接；正常应用仍走原启动链，生产不包含预览入口。

### B. 代表性样例与设计交接

主 Agent 选择当前有需求的一个组件制作草稿；具体领域文件在开始前加入任务包，不以本节授权任意修改现有面板。

- 允许范围：预览目录内的注册表和内存样例；额外领域文件仅按具体任务包授权。
- 完成条件：复用实际展示组件；列表、详情、返回可体验；内容多时容器可滚动；确认后交接组件、Props 与设计边界，不按截图重写。
- 后续真实业务接入属于该面板自己的任务，不自动包含在入口建设中。

### C. 局部文档与验收记录

- 允许范围：`apps/studio-client/README.md`、本 Plan、相关索引；按需要更新 Guide 中的待实施状态。
- 完成条件：README 给出已验证 URL、启动和注册方式，本 Plan 如实记录实施和未验证项。

## 完成条件与验证预算

- 本轮文档交付：文档链接与生命周期检查、相关 Diff 检查；不运行应用测试或构建。
- 未来入口实施：相关 Client 类型检查，以及一次定向生产构建检查，验证开发入口和样例不会被发布。
- 用现有测试能力或明确授权的客观浏览器诊断验证预览不发认证/RPC、不写持久 Storage，正常路由仍遵循原认证流程；不要通过实际修改用户业务数据验证。
- 样例的观感、间距、滚动和窄屏体验由用户确认；没有确认则记录未验收，不以类型或构建通过代替。
- 每项风险指定验收人和证据，主 Agent 不默认重读实施者全部内部链路，不重复前提未变化的验证。

## 停止条件与开放问题

- 需要新增依赖、改变生产认证、修改后端或扩大业务组件写入范围时停止并重新确认。
- 首个真实样例及其领域文件范围在实施启动时选定；未选定前可以设计入口，但不能自行重做整个业务面板。
- 现有主题初始化是否耦合 App，需要实施时从入口定向核对；优先最小复用，不为此启动 Shell 全面重构。
