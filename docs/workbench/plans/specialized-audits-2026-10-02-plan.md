## 目标与非目标

分别审查前后端 API/IPC 对接、内存、前端 UI 组件及 TSX/SCSS 复用。不是再次执行一般 Bug 大审查；已确认 OCT 问题只引用，不重复计数。

不修改源码、测试、依赖、配置或业务数据；不新增接口或公共组件；不提交、推送或部署。内存专题不扩展到 CPU、帧率和渲染速度。

## 最小验证与停止条件

- API 候选追踪 UI → Client API → RPC → Runtime/Store → DTO，不把完整编辑树或真实全局搜索的必要全量读取误报。
- 内存候选给 owner、规模与释放条件；有界小探针可以计数，不进行 OOM 压测，不把静态估算当堆快照。
- UI 统计排除开发/归档入口；原生标签命中不是重复组件数量，至少核对现有组件 API 与交互差异。
- 每项区分确认缺陷、优化候选和未证实风险，给最小收敛方向及验收条件。
- 只对具体风险运行必要的定向验证；不默认执行全套 lint/typecheck/test/build，不启动浏览器纯视觉验收。
- 三个分域都有有证据的结论和覆盖限制后停止，不凑数量。若未来修复会改变公共契约、权限、持久化或生命周期，单独提出决策，不在审查中实施。
