# 工作区导航与统一入口

状态：核心实现和定向验证完成；人工观感验收未执行。用户已确认，2026-09-23。

## 目标与边界

普通启动恢复上次工作区；应用内面板、资源、Timeline 导航使用浏览器历史状态，地址栏不随每次选择改变。资源 URI 标识目标，外部 URL 只承担统一入口和显式深链。明确深链优先于恢复记录；缺失对象显示不可用，不自动改绑。编辑撤销、草稿、展开与滚动不作为导航历史。

复用现有 loom-resource URI、React Router、safeLocalStorage 和布局 Store。不新增全局路由框架，不改 Agent/CodeAct、数据 Schema 或后端。旧的现有显式路径入口仍能打开，但应用内不再依赖这些路径切面板。

## 最小施工

1. 主代理：studio-route / use-studio-navigation 负责位置结构、入口解析、同 URL 历史及按 endpoint 的恢复；main / App 接线，显式 Timeline 加载不因面板关闭丢上下文，修复缺失入口。
2. A：复用 EntityReference 增加 Timeline Branch/Node 和资源 Node 定位，统一入口 URL 与异步目标解析，严格保留快照引用原语义。
3. B：引用查看器改为受控 UI，不自行操纵地址栏，实体打开复用 URI。
4. 主代理：资源选择接入导航，关闭面板不卸载已访问宿主；同步 issue。

## 验证与停止条件

主要风险：返回/前进丢 Timeline、启动恢复覆盖深链、无效目标静默替代、面板关闭重挂载。用真实 Memory Router 的控制器测试覆盖统一入口、同路径历史、恢复优先级与坏存储；URI/解析器定向测试；入口表与宿主检查；Client 类型检查用于跨模块集成。必要客观浏览器诊断可执行，不做纯视觉验收，不把单测当成真实性能证明。

仅保存位置 ID 和查询条件，不保存正文或密钥。布局/草稿沿用原所有者。遇到未决定的持久化或权限合同才停下询问。
