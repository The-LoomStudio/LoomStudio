# Fake Provider 真实链路调试计划

状态：方向已确认 / 待实施；2026-11-04。本次授权为编写 Plan，不包含业务实现。

## 目标

将内置 Fake Provider 从回声响应升级为创作者、用户和开发者共用的低成本调试工具。模型响应可以模拟，Prompt 构建、Agent Run、工具执行、审批、持久化、事件和模型日志必须使用正式链路。后端测试、运行中的服务和前端共用同一套场景执行实现。

这是正式产品开发路线的一部分，不是测试目录中的专用 Mock，也不是另造一套 Agent Runtime。用于稳定复现链路缺陷、验证修复及辅助后续审计；不能替代真实 Provider 的协议、网络和模型行为验收。

## 已核实的起点

- `packages/ai-gateway/src/fake-provider.ts` 读取最后一条用户文本，返回 `Agent draft: ...` 完整 Chat Completion，usage 为零。
- `packages/ai-gateway/src/provider-registry.ts` 的 `official.fake` 声明不支持 streaming 和 nativeFunctionTools。
- `packages/ai-gateway/src/capability-registry.ts` 注册的 Fake `chat.completions` handler 只向回声实现传入 messages 与 providerCallId。
- `packages/ai-gateway/src/profiled-gateway.ts` 提供 Profile/Capability 调用及 Run 包装；`gateway.ts` 另有正式模型流处理路径。Fake 到实际 Agent 消费与完整模型日志的衔接尚未完整追踪，不能据注册入口推断已接通。

以上为 2026-11-04 局部源码核查，不是运行验证。工作区存在其他任务修改，实施前按相关路径重新核实，不回滚或混入无关改动。

## 已确认边界

```text
用户操作 / 后端测试
  → 正式 Agent Run → Prompt 构建 → Gateway / 模型调用记录
  → Fake 响应端
  → 正式流处理 / 工具执行 / 审批 → 工具结果回传
  → 下一次模型调用 → 终态持久化 / 事件 / 前端展示
```

Fake 只负责模型侧的输出内容、时序和指定故障。工具调用由正式执行器处理，不能直接伪造工具结果跳过执行。无副作用测试采用明确的测试工具与临时工作区；应用内执行仍遵守现有权限、审批和真实副作用规则。

不新增通用工作流语言、可视化流程编辑器、独立日志系统或另一套 Run 状态权威。无需为了“真实”强制把本地 Fake 绕成 HTTP 服务；真实业务链路与外部网络协议测试分开。

## 最小能力与职责

### 场景定义

首版使用可校验的结构化步骤，表达文本输出、工具调用、等待、失败和结束。可配置流式分块及间隔；reasoning 在正式通道支持的范围内接入，不将它拼入正文伪装支持。

场景可跨模型轮次：第一轮请求工具，第二轮检查实际回传的对应工具结果再续答。检查对象是正式请求中的消息、工具声明及关联 ID。条件不满足时明确报错，不能静默回退为默认回复。优先固定步骤和少量匹配条件，不提供任意代码执行能力。

预置场景先覆盖：正常流式回复、工具调用后续答、审批暂停与恢复、首包前失败、部分输出后失败、取消。迟到响应作为明确启用的故障场景追加，不污染默认取消语义。

### 一次调试执行

场景定义与执行状态分离。每次运行捕获场景版本或不可变快照，记录调试执行身份、关联 Agent Run/模型调用、当前步骤、等待原因与错误。同场景并发运行相互隔离，不使用进程级共享游标或请求计数判断轮次。

重跑创建新执行，保留旧日志。场景编辑影响后续执行，不能改变正在执行的步骤。独立 Capability 调用也应获得自己的执行身份，不强行伪造 Agent Run。

暂停、继续、单步和取消由后端拥有；前端卸载不销毁后端已受理任务。暂停需明确是 Fake 输出检查点，还是既有工具审批状态，不能混成一个含义不明的 paused。取消释放定时等待、监听和实例引用。

首版建议只恢复查看已记录事实，不自动恢复进程重启前的调试执行，不自动重做工具副作用。具体状态落点与中断标记在第一阶段结合现有 Run 恢复合同确定；不得默认为已支持持久单步恢复。

### 日志与状态检查

所有模型调用继续进入正式观测链，记录实际输入、输出、工具请求、耗时、错误与取消；复用现有敏感数据策略。附加场景 ID、调试执行 ID、步骤位置等关联信息，不把调试元数据混入用户正文或 Prompt。

真实耗时、真实工具结果与持久化状态按实际记录。场景指定的 token usage 必须可辨认为模拟数据，本地 Fake 不产生外部模型费用；不得把模拟 usage 混算成真实支出。诊断接口不返回凭据。

### 使用入口

- 后端测试：使用临时数据库/工作区与正式 Runtime，直接选择场景，无需浏览器或真实付费 Provider。
- 后端进程：通过同一服务入口启动/查询/控制，运行不依赖页面存活。
- 前端：复用模型选择、观测及设置组件，增加场景选择、步骤展示和运行控制，不另建复杂调试工作台。
- CDP：借助后端可查询的暂停检查点控制浏览器动作，复现刷新、切会话、断连和迟到结果；不是用任意 sleep 猜测执行阶段。

## 交付顺序与验收

| 阶段 | 工作及责任边界 | 完成标准 |
| --- | --- | --- |
| P1 真实调用闭环 | 追踪现有 Agent→Gateway→Provider→日志；在 ai-gateway 扩展 Fake 响应能力，在实际消费层接入，不旁路工具执行器 | 正式 Run 收到工具请求，真实执行工具，将结果交给下一次 Fake 调用并得到续答；正式日志可关联各轮；正常结束与工具失败均可解释 |
| P2 可控生命周期 | 在后端拥有场景实例与控制，补流式、等待、单步、取消、故障及并发隔离；RPC 只做正式服务适配 | 两个并发执行不串步骤；等待中可取消；中途失败保留正确的部分输出/终态；结束释放资源；前端断开不改变后端事实 |
| P3 前端与审计使用 | 复用现有模型选择及观测界面，添加必要控制；整理预置场景与使用说明 | 创作者可选场景完整跑一轮；开发者无需页面可跑同一场景；浏览器通过可查询检查点复现至少一条切换或刷新链路，日志能定位结果 |

P1 开始时必须回答的实现问题：Agent 的实际 Provider adapter 接口是什么；Fake 两个注册入口如何共享实现；现有模型日志的所有者和关联字段是什么；跨调用执行身份如何传递。先形成最小文件级设计，不凭本 Plan 猜造新 API。若需改变公共契约、权限或持久恢复语义，应把具体差异回传确认。

场景执行核心归 ai-gateway 的 Fake 实现；Agent 仅传递执行关联并消费标准响应；调试实例的应用级生命周期归后端现有服务层；前端只操作和投影状态。具体文件拆分在入口追踪完成后确定，不按概念提前建立大量模块。

## 验证预算与关闭条件

沿用现有测试工具，选择能验证真实边界的少量集成用例，不搭建新测试框架。优先验证一次工具闭环、两次并发隔离、取消等待、部分输出失败以及正式日志关联；不能 Mock 掉正在验证的 Agent、工具执行器或持久化核心。

后端测试证据不等于浏览器通过；HTTP/流事件检查也不等于真实 Provider 协议通过。CDP 验证只针对明确的交错场景，使用隔离数据，不把视觉巡检或真实外部调用作为默认步骤。

阶段完成记录具体结果与限制。全部首版阶段交付后归档本 Plan；持久恢复、更多协议模拟或复杂场景编辑只有存在明确需求才另行计划。当前没有实施、测试运行或浏览器验收结果。
