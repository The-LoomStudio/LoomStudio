# 扩展模块补全

> 状态：待调研 / 未实施
> 创建：2026-10-02
> 本轮授权：单独建立后续 Plan；不代表授权实施未决的远程执行或权限策略。

## 目标与已确认边界

让玩家通过远程链接安装独立发行的扩展，不依赖主程序仓库内的开发扩展目录。
覆盖 GitHub 与其他 Git 托管来源；ZIP 不作为玩家主要安装流程，
但可以作为远程发行载荷或离线辅助方式。

沿用现有扩展安装、发现、Manifest 校验和模块授权体系，不建立平行安装器。
安装、授权与启用是不同动作，不能因来源标记为官方而自动授权。
ST 兼容导入和 The World 均为独立、可选扩展；
ST 导入是前期过渡扩展能力，不是主程序原生能力或启动前提。

本计划承接[发布计划归档](../../archive/plans/node-release-and-player-installation-plan.md)。
Beta 主程序的统一启动与发行目录已交付，不在此重复改造。

## 当前基线

发布阶段确认已有本地目录/ZIP 安装和扩展发现路径，
尚未实现远程扩展发现、下载与安装链路。
生产启动不扫描仓库开发扩展；正式扩展必须通过安装路径进入用户目录。
同 ID 多来源冲突、更新和替换不能以重复安装冒充升级。
开始实施前需要重新核对当前源码及独立官方仓库的发行产物，不以本记录代替实时证据。

可执行 Server 扩展属于可信同进程代码，不是安全沙箱；
Host 的模块权限不能阻止扩展直接调用 Node.js API。

## 未决事项与停止条件

- 远程链接的正式输入合同：仓库、固定版本、提交或发行产物如何定位。
- 是否只接受预构建产物；源码构建、依赖安装和生命周期脚本是否允许执行。
  当前不授权自动执行任意第三方脚本。
- 下载与 Git 获取的来源、安全及网络边界，包括重定向、内网地址、凭据处理和允许的协议。
  不预先制造整套白名单/黑名单配置，先确认真实安装路径与威胁边界。
- 官方扩展如何提供稳定安装链接与兼容性信息；首次推荐、选择安装或随 Release 携带仍未决定。
- 同 ID 重复安装、更新和替换的合同，如何保留扩展数据并处理失败。

这些事项涉及公共契约、权限或持久化语义，证据不足时需向用户确认，不能自行决定。
内容外链/CSP 策略不是安装来源策略，本计划不顺带修改。

## 最小执行路径

1. 核对现有安装器、发现、授权、持久化及官方仓库发行产物，
   列出玩家从链接到启用之间的具体缺口。
2. 确认远程输入、获取/构建与更新合同，再补充文件级实施范围。
3. 复用现有安装提交路径接入远程获取，接通界面进度与可操作的失败提示。
4. 使用预构建扩展验证下载、校验、安装、授权、启用与重启后的发现；
   将本轮失败语义与剩余限制写回 Plan。

## 验收与非目标

主要验证是从独立临时用户目录通过远程链接安装一个真实预构建扩展，
完成 Manifest 校验、显式授权/启用，并在重启后正常发现。
覆盖真实信任边界上的非法来源、无效产物和获取失败；
失败不能留下可被当作成功安装的半成品，也不能破坏已有扩展或用户数据。
具体可执行命令和测试范围在合同确认后补齐。

不实施 npm 主程序发行、Electron、移动端、自动更新框架或凭据明文降级。
建立此 Plan 不宣称远程安装已经完成，也不承诺 Beta 数据恢复能力。
