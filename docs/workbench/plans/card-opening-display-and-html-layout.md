## 目标与边界

- 未进入 Timeline 时，角色卡开场白也经过当前角色卡、预设和公共规则的 Display 投影；只读、不创建 Timeline、不落库。
- 复用现有规则引擎、SkeletonText 与 iframe 隔离，不增加依赖，不兼容新的 ST 宏或交互 API。
- 消息 iframe 提供加载占位、同内容／宽度／主题的有界内存高度缓存；用户最新决定取消高度上限与宿主强制内部滚动，不提供展开按钮。独立 HTML 块之间由宿主保留 12px 间距，不修改作者文档内部布局。
- 正式 Timeline 的 Display 按用户最新批准改为读取当前卡片源规则并应用自身 Override；Prompt／Classify 与 Extractor 保持原冻结语义。开场白预览不冒充正式历史，不修改已有会话正文或快照。
- 用户追加的长代码溢出：修正 RendererNodeMountHost Grid 的最小列宽与 Markdown pre 盒模型，横向滚动仅发生在代码块内部。
- 用户提供的压缩 HTML 附件仅静态解析，不执行其脚本；裸文档已识别成功。用户随后确认 replacement 自带代码围栏；显式 text 围栏仍保持源码语义。

## 文件与实施顺序

1. application-runtime/transforms：为纯投影增加开场白来源身份，新增只读预览方法；服务端 Text Transform RPC 和客户端 API 对应接线。
2. message-content 与 App/NarrativeTimeline：以 endpoint、角色、预设、文本和刷新版本隔离预览请求，显式展示等待／失败。
3. message-content/HtmlPreview：实例加载占位、尺寸缓存、随内容展开、块间距、有限淡入及 reduced-motion。
