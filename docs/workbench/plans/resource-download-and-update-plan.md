# 作品、角色包与扩展：资源下载与更新

> **状态**：实施中 / 2026-11-07 已授权
> **更新**：2026-11-07

## 1. 目标、范围与原则

为作品／角色包、预设与扩展提供来源解析、后端下载、依赖准备、版本检查、更新提醒，以及简单的一次性内容比较和采用。讨论顺序保持：下载链路 → 更新检测与通知 → 导入、内容保护与生效。

- 作者自由选择 Git、Release 或文件托管；平台要求获取结果完整可用，不强制 GitHub、Release 或所有资源都采用 ZIP。
- 来源扩展理解平台差异，宿主负责共同下载与资源操作。安装、资源采用、授权和运行启用保持不同职责。
- Diff 面向读者，优先简单比较和选择，不建设 Git 式合并工作台、持久逐项审阅账本、复杂依赖可视化或通用 Asset 对比器。
- 复用现有包编解码、安装器、资源复制、State、日志和通知能力，不建立第二套资源数据库。
- 本计划不包含主程序打包、自更新、启动器或 PWA；不建设 Marketplace、通用依赖求解器、自动语义合并、全历史迁移或旧运行时多版本共存。
- “作品包”是用户侧称呼；先沿现有 Card Bundle 表达，不据此新增领域类型。作者源与 Timeline 运行材料仍保持各自权威。

## 3. 下载链路（已确认）

### 3.1 作者分发与用户链接

开发工作区与用户安装用途分开，不按是否使用 Git 区分开发态。简单 JS／纯资源可直接从 Git 获取；需要构建的作者可用 CI 或本机构建并上传成品。宿主不自动执行依赖安装或作者构建脚本。The World／ST Data 的成品发布建议不扩大为全平台规则。

分发声明放在已有 Manifest 的可选字段中，支持 Git 地址及 ref、Release 平台／仓库／附件选择、文件直链。字段与接入合同见[下载服务说明](../../../apps/studio-server/src/resource-downloads/README.md)。仓库首页需要发现发行内容时，仓库中应可读取声明；运行入口完整性在取得成品后校验。

| 输入 | 获取行为 |
| --- | --- |
| GitHub 仓库链接 | 通过内置适配识别可选发行内容与仓库直接获取方式；不盲目把源码当安装成品 |
| Release 列表／具体页面 | 列出或选中版本；附件唯一明确时继续，有歧义则选择 |
| Release 附件／普通 CDN 文件直链 | 下载指定文件，之后核对包内容 |
| 直接运行的 Git 扩展 | 获取明确 ref 对应内容 |
| 角色包文件（含 GitHub 托管文件） | 按具体文件下载，不因此创建 Git 工作区或跟踪分支 |
| 本地文件 | 用户选择上传，进入同一后续解析流程 |

Release 是托管方式，不是压缩格式；当前扩展压缩包安装器支持 ZIP，其他格式按实际需求另定。自动附带的源码归档不等于构建成品。包必须包含 Manifest 声明的入口与运行资源，不强制目录叫 dist，也不强制包含 src。当前全局扩展默认安装到程序的 extensions/<Manifest id>，运行数据另存；下载安装路径仍复用各领域现有规则。

普通入口首版支持公开 HTTPS 与明确适配的 Git／Release 链接，不解析任意网盘分享页、提取码或登录网页。平台扩展可在授权范围内支持自己的登录协议。查询失败不能当成无发行版后静默改下源码。

### 3.2 任务、暂存、依赖与日志

流程：用户提交来源 → 后端获取主包 → 校验并放入受管理暂存区 → 读取／解包清单 → 展示补充依赖 → 准备依赖 → 等待导入或安装。

- 远程下载统一由后端执行；前端消费状态、进度、错误与结果，提供取消、重试。离开面板不自动取消任务。
- 首次下载与更新复用暂存能力；下载成功不覆盖 SQL 资源或正式安装。未知总量显示阶段或已下载量，不伪造百分比。
- 主包进入暂存后再显示补充依赖，不要求下载前已知全部依赖。复用现有依赖检查；满足版本的已安装项可复用，冲突明确反馈，不静默升级其他作品正在使用的依赖。
- 包内携带、外部引用和安装依赖分别处理；引用不自动授权抓取或执行。配套下载不等于双向同步或持续自动跟随作者。
- 下载、安装、资源采用、授权和启用结果分别表达；跨包不假定一个全局事务。部分失败显示实际完成项与可重试步骤。
- 复用日志体系，按任务关联获取、校验／解包、依赖准备、完成、取消和失败。前端状态不从日志文本推导；不把每次进度变化持久记录，不泄漏凭据或敏感 URL 参数。
- 断点续传不是首版前置要求。暂存保留与清理、任务跨服务重启恢复程度、并发数和进度传输方式在实施设计时收束。

## 4. 来源适配与更新检测（已确认方向）

### 4.1 最小共同能力

GitHub 是内置来源适配的一个案例；Odysseia 等平台可开发扩展使用自己的 API。统一适配结果，不要求所有平台实现同一种 HTTP API，也不要求宿主托管作者资源。

| 动作 | 输入 | 输出 |
| --- | --- | --- |
| 解析来源（必需） | 链接或保存的来源引用 | 资源身份、展示信息及候选版本 |
| 准备下载（必需） | 资源与明确候选版本 | 当前有效的文件地址或 Git 地址＋明确 ref |
| 检查更新（可选） | 来源引用与当前采用版本 | 有新版及候选／无新版／不支持／检查失败 |

最低数据：适配器、来源站点与来源资源 ID；来源版本 ID 与已知 Manifest 发布版本；下载目标和可选大小／摘要；名称、类型、作者页面及可选变更说明。来源 ID、包 ID、本地资源 ID 分开；临时 URL 不作为长期身份。未知字段下载后补齐，不冒充已验证。

简单作者只提供文件也能导入，增加静态远程 Manifest 后可查更。平台扩展负责登录、作品目录、权限与版本接口，可创新推荐、收藏、订阅和收件箱；具体下载、暂存、提醒和资源采用仍交宿主。来源扩展不自行覆盖玩家资源。

用个人作者＋静态 CDN、GitHub 仓库／Release、Odysseia 登录＋平台版本 ID＋临时 URL 验证接口。平台适配器需要其运行环境，不保证停用后仍能查更。

### 4.2 链接与凭据

- 适配器声明域名／路径；唯一匹配直接使用，多匹配让用户选择，无匹配才尝试通用直链。既有来源关联不被新装适配器自动抢占。
- 停用／卸载适配器保留已导入内容与来源记录，暂停相关检查及新下载，显示来源不可用。
- 宿主凭据存储保管账号凭据，适配器按授权访问；不进入 Manifest、导出包、普通记录或日志。断开账号和删除凭据独立于卸载，以免影响共享连接。
- 临时 URL 过期重新解析同一选定版本；需登录时保留任务并提示，不偷换为最新版本。CDN 地址变化可重解析，跨站点／仓库／适配器迁移须确认。

### 4.3 版本与候选校验

- 包发布版本依据 Manifest，采用统一 SemVer 方向，允许标准预发布后缀；不开放作者任意比较脚本。来源版本 ID 可是不透明标识，不按字符串排序。精确字段和旧包异常版本处理待设计。
- commit／摘要标识实际产物，不因每次提交变化默认提醒新版。同版本内容变化可在详情提示并允许主动重新获取，仍经过内容选择和授权。
- 正式渠道默认只提醒更高正式版；预发布由用户主动选择，并可转入后续正式版。固定版本／Tag／commit 暂停常规升级提醒，允许手动查看其他版本。
- 远程 Manifest 或适配器提供候选，下载后核对包 ID、发布版本及兼容要求。明确声明与包内不一致时保留暂存、报错，不作为原候选采用。来源 ID 不要求与 SemVer 相等。
- Git 检查和获取应绑定同一提交；主分支版本不必然已发布，远端声明先于产物或文件被替换时明确反馈。ZIP 字节不同不等于内容必然不同。
- 简单来源可在 Manifest 中提供远程 Manifest 地址，不强制新增元数据文件。不支持检查、请求失败与已是最新是不同结果。

### 4.4 调度与提醒

启动时距上次检查超过 24 小时则后台检查，长期运行约每 24 小时检查并错开请求；不阻塞启动。手动检查复用在途任务，支持来源批量查询，遵守限流。24 小时为首版默认方向。

“稍后”保留包级待更新项，同候选不重复弹窗；“忽略此版本”仅忽略该候选。已下载未采用显示待处理，不反复要求下载，也不视为采用完成。来源、采用版本、候选、检查结果、忽略记录与暂存关联跨重启保留。这些包级状态与下一节不持久化的逐条 Diff 选择不同。

复用现有通知入口，不以此建设通用通知中心或 Web Push。

## 5. 内容比较与副本（已确认）

### 5.1 一次性 Diff

更新时比较新版卡片／包内容与当前 SQL 资源，展示简单差异，由玩家决定保留本地或采用作者内容。排序、条目增删、正文与宏变化用同一类直观视图处理；不把玩家当成 Git 开发者，不让用户解决宿主推测出来的语义依赖图。

确认完成后提交最终内容并结束临时工作区。不持久化逐条“已审阅／暂缓”，不长期显示“已审阅”或“含本地修改”标签。下次重新比较，同一差异可以再次出现，不建设审阅基线推进账本。两侧比较不推断作者／玩家各自的历史改动归属。

例：作者新版宵禁为 21:00，玩家保留 23:00，SQL 继续保存 23:00。来源采用版本可记为 1.3.0，但不表示每个本地字段都等于作者原版。来源记录、包备份和恢复所需事务信息仍有各自职责，不等于逐项审阅状态。

| 内容 | 玩家展示与边界 |
| --- | --- |
| Lore／世界设定 | 主要审阅内容：条目与正文差异、保留或采用 |
| 预设包 | 主要审阅内容：条目、角色、顺序、正文与宏定义；运行时用户值不当作作者默认值覆盖 |
| 代码、Script | 默认只显示更新摘要；声明新增权限／能力等需要处理时再显示，不默认要求看源码 Diff |
| 正则／提取器 | 保护用户修改，必要时简单选择保留或采用；源码比较不是普通玩家默认流程，不重建已迁移旧资源类型 |
| 扩展配置 | 由所属扩展维护，宿主提供存储不代表理解语义；普通新增设置或保留值不逐项提醒 |
| Asset | 不建设通用图片／音频／二进制对比器，按需显示更新摘要 |

保留现有结构、权限、引用和版本校验；已知不合法时明确报错，不承诺理解任意代码的隐含耦合。预览后发生编辑时，不能用过期预览覆盖新状态。手工编辑可复用现有编辑能力，不将精细三方合并作为交付前提。

### 5.2 整份另存副本

- 保留我的内容：原资源保留玩家版，不创建副本。
- 我的版本另存为副本：复制当前本地整份 Lore 或预设，允许命名，默认附加“我的版本”；首版不将单条抽成新资源。
- 副本使用新身份，成为独立个人资源，不跟随原包更新。预设保留排序、正文和宏配置；外部 Lore、工具、脚本保留合法引用，不递归复制依赖、不复制故事。
- 原消费者仍引用原资源，不自动切换、不同时启用两份 Lore；另存不自动替玩家决定原资源是否采用新版。
- 保存成功显示“已保存到个人资源”和查看入口，立即持久化。后续取消更新不删除副本；失败明确反馈。
- 复用现有复制与引用映射合同，不能仅删除 origin 就伪造独立副本。

## 6. 生效、失败与恢复

角色卡内容、Lore 和预设从下一次 Agent Run 消费，不触发当前 Run 重新构建 Prompt，不改变在途请求。内容采用不改写既有正文或 State。

代码切换复用运行生命周期，不能把“下一次 Run 生效”解释为可以热替换正在执行的代码。需核对 Script／Renderer／服务端模块的清理及下次启动入口，必要时局部重载或等待受影响任务结束；不默认全应用重启。扩展代码版本和贡献资源采用版本分别记录；共享扩展与角色私有安装按已有作用域处理，不混同“角色包”与独立系统进程。

失败按实际阶段反馈。例如内容已保存、面板启动失败，则提供相关实例重试，不要求重复整次更新；恢复前检查后续修改，不能静默覆盖。文件、SQL 和运行实例不假定全局原子事务，代码回退不等于数据逆迁移。

## 7. State：作者兼容逻辑与宿主基础 API

作者负责迁移语义和旧数据兼容，可放在独立脚本或主模块中提供检测／按钮；不强制脚本文件形式。宿主补齐最小 API，不按 Schema 自动猜转换，不让 AI 默认清理组件，不保证所有旧存档在作者破坏性更新后仍能运行。

### 7.1 复用和补齐

- 既有 Schema 范围内转换复用 state.read/write、expectedRevisionId、幂等和不可变 Revision。
- Schema／组件结构切换需要受控提交定义与结果，检查权限、作用域、并发和新定义，不允许普通文档写入绕过约束。接口形态待实施设计。
- 当前 Schema 保存在 Timeline Runtime Context，同故事分支共用；State Head 逐分支独立。只迁移当前分支不代表其他分支完成。作者可用容纳旧新结构的定义配合自身兼容逻辑；收紧定义时如实暴露不兼容。
- 先核查最小增量，不默认新增 Revision 级 Schema 模型或旧运行时多版本系统，不为完美历史兼容扩张架构。
- Schema 当前为 JSON Schema 子集，非 Zod，默认 type: object 宽松。补齐作者可见的支持范围与不支持关键字反馈，不默认换库或实现完整标准。

### 7.2 历史和分支

普通写入创建新 Revision、推进指定分支 Head；节点关联历史状态，撤销通过补偿 Revision。保留该能力，不增加原位覆盖整条历史的 API，不默认扫描迁移全部故事／分支。

作者可在分支进入相关功能或执行前检查结构版本：缺字段时补值并产生新 Revision，或只在读取时提供业务默认解释；已经存在的值不重复初始化。只浏览历史不应因此迁移。具体生命周期 API 是否足够需核对，不冒称全部已有。

例：雾港故事 A 主分支第 18 天、余额 850、有灯塔；旧分支第 12 天、余额 420、无灯塔；故事 B 第 3 天、余额 160。新增 reputation 时按作者逻辑仅处理当前使用的分支，不把 A 主分支结果复制给其他分支，不动旧 Revision。初始金钱变化不重置现有余额。

新版代码不支持旧钱包结构且作者未提供转换时，允许明确报错或暂停相关功能，宿主不猜测修复。业务不兼容可以存在；权限、事务、并发与存储完整性仍由宿主负责。State 数据结构版本与扩展发布版本不能混同。

## 10. 实施前剩余设计与完成标准

产品方向不重复审批；以下只收束落实所需的合同，遇到明显改变行为的选择再讨论：

1. 来源适配 SDK 的字段、能力、错误及授权范围；分发／检查声明字段，包身份匹配与旧包缺失／非法版本的行为。

3. 一次性 Diff 对排序、删除和宏的最小表现及结果提交；复用资源复制，确保新身份、内部引用映射与合法外部引用。取消审阅不保存选择，已另存副本保留。
4. 运行实例的最小切换入口，以及 State 定义受控切换与作者生命周期 API 的必要补齐；不扩展到全历史兼容。

完成需以真实路径证明：

- 三种来源案例可解析，目标候选明确；后端完成下载暂存和依赖准备，进度、取消、重试与日志结果准确。
- 检查失败／不支持不冒充最新；版本和候选校验有效；忽略及包级通知状态按约定恢复。

### 第二轮：复杂 Card 接续与作用域（2026-11-07）

用户授权继续实施。本轮沿 Runtime 负责原子资源采用、Server 负责归档与媒体 IO、Client 负责简单摘要的既有边界扩展：

- **载荷与扩展归档**：载荷以 artifactPayloadId/packageId 保持身份；内嵌扩展以 packageId→Blob 映射证明归属，保存新归档并保留独立附加内容。更新归档不安装、不启用、不更新已采用的扩展资源；用户继续走现有角色扩展安装／更新流程。归档内部校验仍由安装流程执行，保存不等于安装验证通过。
- **媒体**：头像和背景使用现有 AssetStore；用户可保留当前媒体，不建设 Asset Diff。下载包字节摘要与 Runtime fingerprint 共同约束确认结果，媒体引用和内容同次 Card CAS 提交。AssetStore 目前独立写入，最后 CAS 失败可能留下未引用资产，不能通过删除底层 Blob 清理共享内容。
