## 已有基础

- 角色保存目录与运行数据库分离：Studio 普通编辑后显式保存；目录文件可显式校验并 Apply 到原角色，不创建重复 Card。
- 基线、原对象身份、CAS、共享写入拒绝及中断恢复由现有目录服务与 Runtime 管理。Timeline 运行数据不回写作者初始化。
- 目录可携带真实正文、State 声明/初始化、脚本、媒体及额外作者文件。文件格式、附件完整性和独立资源分发继续由 Data 与各领域计划负责。
- 文件存在、显式 Apply 和媒体刷新不等于 Studio/Agent 已具有工程文件编辑权限，也不等于自动构建、执行或热重载。

实现入口：`apps/studio-server/src/resource-directories/`、`packages/application-runtime/src/runtime/card-directory-sync.ts`。这些是后续可复用基础，不要求重新通读或重写文件编解码。

## 保留的方向与边界

- 普通游玩继续以 DB 编辑、显式保存为默认体验，不强迫所有用户进入工程开发。
- 曾讨论的“明确进入开发模式后以文件为编辑源”保留为待细化方向，不视为完整模式切换与同步合同已获批准。
- 内部 Agent 不因项目打开而获得任意主机路径、Shell、构建或执行权限；允许写脚本不等于允许执行脚本。
- 复用已有角色目录，不强迫作者另开一份文件夹；源码、嵌套 dist 与资源组织沿用已有包合同，不另造包管理系统。
- CLI/MCP 的连接、认证与命令投影由[适配器计划](./application-capability-cli-mcp-adapters-plan.md)负责。开发模式和最小 CLI 是否互为前置，待具体切片讨论，不能制造循环依赖。

## 动工前必须讨论

1. **最小体验**：是否需要显式模式开关，还是先提供受限的打开工程/编辑/应用操作；支持哪些资源和用户工作流。
2. **编辑源与切换**：未保存的 DB 修改、IDE 修改同时存在时，如何进入/退出开发模式；避免两份内容无提示互相覆盖。
3. **草稿与提交**：无效文件如何保留、何时应用、多资源提交失败如何呈现、关闭页面或服务重启后如何恢复。防抖不能替代事务语义。
4. **权限与 Agent**：允许读写哪些文件、如何限定当前工程、如何确认修改；复用 Agent Context/Target 合同，不因选中角色推导管理员权限。
5. **同步与身份**：首版是否保持显式 Apply；新建、删除、移动资源及共享原件编辑如何处理。现有受限 Apply 不代表这些操作已全部支持。
6. **代码开发**：构建、依赖、代码复用、SDK、热重载与授权分别解决什么当前需求；是否需要官方最小样例，先评估成本再冻结范围。

这些问题由用户与主 Agent 讨论确认后，才形成实施工作包；当前不为它们预设 Schema、命令集、组件或新增依赖。

## 非目标与停止条件

- 不重做 Card 文件化、备份层或打包解包；不改为文件层跨角色共享库。
- 不默认引入自动双向 Watcher、通用终端、语言服务器、公共 UI SDK、自动 Git 提交或任意代码执行。
- 当前只允许需求和方案调研；新增代码、数据迁移、权限扩展或自动执行必须取得后续明确授权。
