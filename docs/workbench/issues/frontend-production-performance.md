### Agent 滚动监听器的释放契约

当前源码中，App 将 `uiState.agentPanelOpen` 传给 Agent 面板。面板经会话视口将活动状态用于滚动跟随 effect 的启用条件。该 effect 在启用时注册六个滚动容器监听器及一个 document 级 `selectionchange` 监听器，并创建 ResizeObserver、MutationObserver。关闭使活动状态切换后，预期清理这七个监听器、断开两个观察器并取消待执行的动画帧。这个源码契约提供了复查目标，无法单凭它解释 DevTools 全页监听器的 189 个跨度。

生产预览仍在监听，Chrome 可读取原页 AX 树，但再次对原生窗口执行操作返回 `noWindowsAvailable`。关闭与回收后基线仍待采样。

### 资源面板关闭后的后台请求

上轮确认关闭时 Network 有 18 条。本轮首次读数为 21 条，面板保持关闭。新增三条按顺序为 `resourceDownloads.listUpdates` 401、会话初始化 204、`listUpdates` 重试 200。切回预览标签后读数为 25 条，又出现同样的三条序列及一条 `getUserProfiles` 200。两段新增记录都没有 `resourceDownloads.list`。

关闭状态下的更新列表请求已有运行证据。单独出现 `listUpdates` 与全局通知的独立查询相符，而对话框的 `refresh` 会同时请求两个列表。Network 的行序验证了会话恢复，尚未用 Initiator 调用栈或精确时间戳确认是哪次查询触发，亦未验证存在进行中下载时的关闭行为。

**发起栈已确认。** 在 Chrome Network 中选中第二次后台 `listUpdates` 的原始 401 行（重试前，29 ms），打开「启动器」。栈包含 `queryFn`（`app-DSRfan18.js:2`）、查询库的 fetch、`useQuery-rrlsBW6V.js:1` 的定时回调及 `setInterval`。源码中对应查询为全局更新通知的 `resource-updates`，间隔 60 秒。该样本的后台触发可以归因到全局查询定时器。对话框仍有独立的成对刷新路径，进行中下载时关闭的行为尚待对照。

**打开面板的成对请求也已定位。** 第二轮打开时的 `resourceDownloads.list` 发起栈从客户端 `list` 进入 `extension-settings-form-B1WfWUIO.js:2` 的两个应用帧，再进入 React 提交阶段的调用。对应产物内的刷新函数将 `list` 与 `listUpdates` 放在同一个 `Promise.all`。结合当前源码中 effect 启动时直接调用 `refresh`，该样本与挂载时成对读取一致。它与关闭后仅出现 `listUpdates` 的全局定时器栈是两条可分别复查的路径。

### 下载进行中关闭对话框的条件

从 `18013` 重新读取本次采样的 `extension-settings-form-B1WfWUIO.js`，确认产物也保留了这一条路径。Launcher 的关闭回调只把 `open` 设为 false，对话框组件仍在父树中。它的 effect 依赖刷新函数，刷新函数只依赖 API。计时器每次等待 1,200 ms 后检查文档可见性和任务状态，发现 `queued` 或 `downloading` 时成对读列表，再安排下一次检查。清理在组件卸载或刷新函数变更时执行。

因此，关闭下载对话框而父工作区仍保持挂载、页面可见且存在进行中任务时，产物中的定时路径仍可发请求。约 1.2 秒是每次等待时间，有请求时还要加上请求耗时。此前浏览器短窗口只覆盖当时的数据状态，未构造进行中下载，也未验证离开整个父工作区时的行为。此项记录为产物确认、运行对照待补。

### 返回正文的清理边界

本次生产页中资源下载入口所在的「角色」工作区走 Studio dock。当前源码在退出动画完成后将 `displayedPanel` 设为 null，dock 的 PanelHost 仍在 React 树中。每个 PanelStage 首次访问后将 `visited` 设为 true，非活动时通过 `hidden` 和 `display: none` 隐藏，并保留已访问内容。角色图库分支仍渲染下载 Launcher 时，返回正文不会因 dock 隐藏而卸载对话框。其定时检查使用的是整个 document 的可见性，和角色工作区是否活动是两个条件。因此仅离开 dock 工作区也不足以保证触发下载 effect 的清理。

这条结论限定于保留已访问 PanelStage 的 dock 路径，以及仍渲染 Launcher 的图库分支。切换图库内部视图使 Launcher 卸载、替换其 key，或卸载整个宿主时，需分别按实际组件树判断。单独打开的扩展管理工具未纳入这条结论。

源码定位见 [StudioPage](../../../apps/studio-client/src/pages/studio/studio-page.tsx#L174)、[StudioPanelHost](../../../apps/studio-client/src/pages/studio/studio-panel-host.tsx#L26) 和 [角色图库 Launcher](../../../apps/studio-client/src/widgets/character-panel/character-panel.tsx#L429)。

### 键盘 INP 异常分解与 iframe 高度链路

生产预览原有实时指标中，最慢交互的目标是 `body`，总计 167,552 ms。展开 DevTools 分解得到输入延迟 64 ms、处理时长 62,265 ms、展示延迟 105,223 ms。同一日志还包含 24–104 ms 的键盘样本和数条超过 100 秒的 `body` 样本。阶段分解显示这条异常主要落在处理和展示，实时日志没有对应主线程调用栈，暂无法归到具体处理器或判定是否受调试状态影响。需要前台新录制重现。

HTML 预览先按内容、容器宽度和主题查找高度缓存，缺失时使用当前壳体高度，零高时回退到 240 px。iframe 在两次动画帧回调后挂载，文档测高后发送 `loom-html-height`，宿主更新 iframe 和外壳高度。这个路径可解释为何预览下方的页脚和按钮会移动，但仍需逐事件对齐以确认最大三次偏移的直接原因。点击实时 LCP 的 `img` 入口未取得图片地址。见 [HTML 预览](../../../apps/studio-client/src/features/message-content/ui/html-preview.tsx#L15) 和 [测高消息](../../../apps/studio-client/src/features/message-content/model/html-document.ts#L26)。

- 0.7128 之前约 9 ms，HTML 预览缓存键读取连续触发样式计算与布局，随后虚拟列表执行 `_retryClampedAdjustment` 并派发 scroll。同帧执行流程矩形从 384 像素高变为 1140 像素高，另有消息区域和页脚移动。
- 约 99 ms 后出现 0.7650，虚拟行从空矩形变为可见。此前紧邻 HTML 预览的动画帧回调、子框架导航以及叙事时间线的动画帧布局。
- 再过约 327 ms 出现 0.7200，同一虚拟行再次从空矩形进入视口，紧邻 `_retryClampedAdjustment` 和 scroll。

开发模式可能改变模块和内容到达的时序。此样本直接支持排查预览测高与虚拟列表锚定的联动，尚无 source map 直接造成几何变化的证据。要衡量上线影响，需用同一会话、视口与恢复位置复录生产构建。
