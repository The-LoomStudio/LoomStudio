## 已确认方向

### 1. 分页按消费者确定一致性要求

- 普通可变列表采用 keyset 方向，统一输入校验与消费 cursor；不为所有列表建设跨请求快照系统。
- keyset 不等于快照。按 `updated_at` 排序时，条目跨越游标仍可能改变遍历结果；不能承诺任意并发下全量不重不漏。
- 导出、初始化判断、删除前扫描等需要完整集合的消费者，分别核对其已有事务或版本保护；不能以改了 cursor 代替完整性验证。
- Document Store 的 Card、Provider、Capability Profile、Agent Profile 和扩展存储消费链，与 Prompt Resource 的服务端聚合读取分别验收。Narrative/Session 的历史链分页和事件流 cursor 不机械改成同一算法。

Document 分页与输入、Prompt Resource 分页及 FR-018 客户端消费已完成本轮修复；独立审查 MD 已删除，验证证据和动态集合边界见[实施计划](../plans/audit-issue-remediation-plan.md)。

### 2. JSON 保真，不收紧扩展领域模型

- 在实际持久化/传输边界拒绝 `NaN`、`Infinity` 等无法按现有 JSON 合同原样往返的值，不静默转换成 `null`。
- 保留合法 `null`、空字符串对象键、现有扩展槽中的自定义字段；不借此扩大业务字段白名单或封死 State Schema 演进。已有领域 Schema、权限与所有权约束仍然生效。
- 迁移或格式转换可以在其明确入口转换源数据，再校验目标 JSON。不能因底层校验而先要求所有外部源数据符合当前领域 Schema，也不能静默清洗旧库。
- 扩展内部临时计算不受此限制；已经持久化为 `null` 的值无法凭空恢复。State Delta 的空键问题单独修复。

State JSON/Delta 与 Prompt Resource JSON 已完成本轮修复，结论和定向验证见[实施计划的已关闭专项](../plans/audit-issue-remediation-plan.md)。

### 3. Card 容器与内部 Assets 分开

- 主要分发形式是独立 ZIP 和承载同一 ZIP 的 PNG，不因内部媒体增加 GIF/视频 Card 外层协议。
- Card Assets 不限于静态头像；GIF、APNG、视频可以是内部素材。保存与打包应保留字节、MIME 和文件身份，不把未知媒体伪装成 PNG。
- PNG 外层需要可显示的 PNG 封面，不能据此限制 ZIP 内的素材类型。既有 Polyglot/旧格式入口的存续另行核对，不在本轮新增兼容分支或擅自删除。
- 现有上传 UI、媒体映射、通用素材清单和播放器并未因此自动获得视频支持。本轮修复现有往返错误；完整 Assets 管理、视频预览和转码单独拆包。
- SVG 复现用于证明 MIME 错配，不构成一律禁止 SVG 或允许执行其内容的决定。

Card 文件往返与 CRC 已完成本轮修复，独立审查 MD 已删除；证据及未验证边界见[实施计划](../plans/audit-issue-remediation-plan.md)。

### 4. 服务关闭先停止接纳，再完成在途业务清理

停止接收新请求，标记 closing，向在途请求传递取消信号，等待业务完成或进入可恢复失败后再关闭依赖。HTTP 连接关闭不等于业务 Promise 已结束；不能把已经提交的数据假装随断连自动回滚，也不能为了停机先关闭仍会被访问的 Engine。

BACKEND-ADV-002 已完成，验证与不响应取消的等待边界见[实施计划](../plans/audit-issue-remediation-plan.md)，不建设通用任务调度系统。

### 5. 允许业务引用失效，Prompt Build 保持宽松

用户已确认不建设跨领域自动引用清理：

- 删除 Provider、Model、Profile 等业务资源，不因存在引用而一律拒绝；保留原引用，等待用户切换或解绑。
- 不自动清空其他资源的配置，不按同名资源重新绑定，不偷偷选择默认模型或预设。临时选中项可以清空，用户明确解绑可以移除关联。
- 列表、详情、编辑页与历史查看必须能承受失效引用，并提供可定位提醒；真正调用缺失的 Provider/Model 等执行依赖时明确失败。一个坏引用不能让整个设置列表打不开。
- Prompt Build 不作为严格编译门禁：缺失的可跳过贡献跳过，无法展开的宏保留原文并提醒，不因缺失统一阻断构建。
- 宽松不等于吞掉所有异常：存储损坏、越权、请求无法执行等仍如实失败。提醒应指出资源/宏与消费位置，复用现有诊断路径。

这替代 [FR-012](./full-repo-code-review-2026-08-27.md) 和 BACKEND-ADV-005 中“一律禁止悬空引用”的旧关闭条件。Provider 子链已按新口径完成，证据归入[实施计划](../plans/audit-issue-remediation-plan.md)；FR-012 其余领域仍开放，不再单凭产生失效引用判断实现有错。

必须保留的存储底线：

- 不允许回滚误删其他已提交或在途请求使用的 Blob；这不是用户主动删除依赖。
- 无引用普通文件可以暂留，当前不要求完整物理 GC。
- 凭据清理失败可以延后，但需保持可追踪状态，不能把秘密信息当成普通孤儿文件放弃管理。
- 不放松同一次数据库事务的正确性、Extension ownership 或 State 版本检查。

当前事实与目标不同：`toAiCapabilityProfileView()` 读取 Provider，目标缺失会影响列表；`deletePromptResource()` 已有清空 Profile 预设与移除挂载的路径，需要按关系语义核对，不能只放开 Provider 删除。宏当前已有保留 token 和 warning 的基础，不重建严格宏编译器。

### 6. Agent 可提交，短期草稿不能反向覆盖新版本

- 前端尚未提交的输入不锁住资源，不阻止内部 Agent 或经正式入口接入的外部编辑提交。
- 无本地改动时跟随最新已提交状态；有冲突时正式版本保留，前端保留用户输入并暂停该旧输入的自动提交，提供恢复/重新应用入口。
- Agent 编辑优先不意味着可以绕过版本检查。所有编辑者都必须基于其实际读取版本写入，不能用服务端临时读取的新版本为旧正文背书。
- 不同编辑源包括 UI、内部 Agent、资源刷新和目录 Apply。IDE 直接修改文件是否生效取决于已有导入/Apply 路径，不假设任意文件变化自动变成数据库提交。
- 自动保存仍有输入到确认之间的窗口。切换资源不串用撤销历史，也不能静默丢弃未保存、失败或冲突输入。
- 只补短期编辑基线、必要版本检查和冲突呈现，不建设持久草稿库、编辑锁或多人协同系统。

### 批次内不能颠倒的依赖

- 数据读取：先确定 Store 排序键、cursor 与输入合同，再修改 Runtime 聚合和 Client 翻页；最后验证多页消费者。不能只替换 SQL，留下只取首页或按旧 cursor 继续请求的调用方。
- 失效引用：先让列表、详情和历史投影能够表达依赖缺失，再放开删除阻拦；必要调用失败与 Prompt Build 的可跳过提醒分别验收。不把“提醒已显示”当作删除链已安全。
- 编辑冲突：先保证写入携带编辑者实际读取的基线，再处理过期查询、草稿投影和自动提交；最后验证 UI 与 Agent 交错。只修缓存或输入框不能阻止服务端接受旧正文。
- 渲染与整理：同一组件先修状态身份、清理和动画所有权，再决定是否移动文件或合并 CSS；不在行为尚未稳定时做全目录搬迁。

首个完整施工单元是批次 1 的数据与启动底线，本轮 JSON/Delta 已收尾，正推进批次 2 的生命周期链。每次只推进一条主链；确实互不依赖、写集不重叠的小项可以独立完成，不为并行度同时铺开全部批次。
