# 多方贡献走查与结构收束 v0

> **状态**：Open Design / Discussion Capture
> **主题**：多方作者需求走查模拟、设计空白账本、官方词汇表与"区 / 块 / 条"结构收束。
> **日期**：2026-07-26

---

## 1. 背景与方法

Zone / Injection Group / Skeleton 这套 PromptBuild 哲学的最终检验标准是：

```text
预设作者、角色卡作者、世界书作者、插件作者
能否互不认识、无法协调地往同一个最终 prompt 贡献内容，
且互不踩脚、冲突可解释。
```

为检验这一点，本次讨论没有审计现有代码（当前实现属早期形态、数据层即将大改），而是做了一场**作者需求走查模拟**：

```text
1. 四位互不相识的虚构作者各自创作并声明投影意图：
   - 预设《织梦者》：定义骨架，自带叙事契约与"必须最后"的一致性守则
   - 角色卡《审判长玛尔塔》：人设 + 条件激活的秘密设定
   - 世界书《埃斯特兰帝国全书》：约 300 条，含互斥 / 递归 / sticky 需求
   - 插件《命运骰》：每回合动态事件 + 状态面板 + fact 供给

2. 一个"人肉编译器"仅以设计文档为规则手册，模拟一次完整 build，
   每一步标注 [规则] / [约定] / [发明]——被迫发明裁决之处即设计空白铁证。

3. 用户视角走查六个真实使用时刻。

4. 完备性质疑者反查模拟本身的误报、夸大与遗漏。
```

触发 build 的回合：用户已进行约 15 轮对话，输入"我走进法庭，向玛尔塔出示了那块带血的怀表。"

## 2. 模拟判例：七个判决时刻

| 判决时刻 | 结果 | 依据 |
|---|---|---|
| 末尾争夺战 | 命运骰 hint 9999 > 庭审仪轨 9000 > 一致性守则 0（未写 hint）；唯一守规矩的作者垫底，意图被反转 | 编译器发明 |
| 未知锚点名 `char.persona` | 卡作者用了另一预设家族的词汇，玛尔塔人设沉入 lower-context，仅留一条深埋 warn | 编译器发明 |
| 战时 / 平时互斥（select-one） | 无选择器机制，按条目 ID 字典序抽签胜出 | 编译器发明 |
| "独断裁决" vs "三席合议" | 一方未用 semantic slot、一方用私有词汇，系统结构上无法识别两段文字描述同一事实，矛盾原样发给模型 | 不可判 |
| 秘密条目的 fact 引用 | 插件改过 fact 名，求值时查无此 fact → 条目静默熄灭；真实数值本应触发 | 编译器发明 |
| 预算超支 30% | 设计明列非目标；三级裁剪顺序全靠发明，同一资产包在不同实现下行为不可复现 | 编译器发明 |
| Zone 折叠为 provider messages | 一致性守则以用户口吻发出、插件事件伪装成用户输入 | ST 惯例 |

用户走查的两个代表时刻：

```text
高光：
  用户拖拽产生的 rankKey 干脆利落压过一切 slotOrderHint。
  "用户终审权"是整套设计回答得最干脆的问题。

暗面：
  换预设后各方声明的锚点名全部查无此名 → 全家沉底、
  历史拖拽随 skeletonId 静默归零 → 用户换回旧预设。
  "内容不绑结构"在跨骨架词汇表这一半上没有兑现。
```

## 3. 空白账本（经完备性质疑校准）

模拟产出的"设计空白"必须分三类，直接引用未校准结论会高估设计的不完备度。

### 3.1 模拟误报：文档其实已答

- "fact 缺席静默无诊断"言过其实——Trace everything 原则保证 `inactive + reason` 必进 Activation Report；
- "用户输入位置无契约"言过其实——README §4.9 已有 current tail 布局；
- 三方争末尾的正解文档已埋——`anti.pattern` 走 merge 语义槽（philosophy §6.2 原生示例），只是模拟中无人使用；
- Activation "不推进 runtime、不调用 tool"已封死插件惰性求值的歧义读法。

### 3.2 文档自列的 open questions

词汇表由谁维护、slot 是否需要 namespace、Skeleton 继承 / patch / fork、slot assignment 由 source 声明还是 composer 决定——均已在各文档开放问题清单中，需要的是排期拍板而非重新发现。

### 3.3 真正的盲区：高度集中在两个薄层

```text
求值语义层（"类型草案已写、求值语义未写"）：
  conditions × triggers 是 AND 还是 OR；
  fact 缺席时比较算什么；
  keyword 扫描多深（仅当前输入？N 轮历史？）；
  defaultActive 缺省值；
  hint 缺席与在场如何比较。
  → 每一条都是两种读法产出两份完全不同的 prompt。
  → 补一份 evaluation semantics 附录可收掉大半。

缺省判决层（"授权框架已写、默认量刑未写"）：
  breakout：预设沉默时默认允许还是拒绝；
  join：默认可否；
  fallback：未知锚点名的精确行为（降级 / 隔离 / 硬错误）。
  → 多方生态的现实是大多数作者不读文档、不写可选字段，
    因此缺省行为就是实际契约。
    缺省语义的优先级应高于可选能力。
```

两层之外需要独立设计的结构题：**词汇表治理**（见 §5）、**fact 生态**（命名空间、悬空引用诊断、改名迁移）、**公地预算**（可牺牲性声明 + 裁剪进 trace 的最小公理）。"意图强度"原列于此，后被 §5 的分类学原理消解。

### 3.4 后续值得单独走查的正交场景

- 预设升级 / 改名：锚点名是外部资产的唯一引用，无别名与迁移机制时一次改名打断全部下游；
- 多卡群聊：两个 persona 声明 single 时的仲裁动词缺失；"当前发言者" fact 词汇未约定；
- 同一资产安装两份：stableId 唯一性作用域未定义，确定性托底机制失效；
- 超长会话摘要化：keyword 扫描面在摘要前后剧变，形成激活漂移循环；
- Regenerate / 分支：lifecycle 的 "turn" 在多次重试下的计数、跨重试幂等性；
- 付费加密资产 vs Trace everything：原则层的内在张力，值得单独一场模拟。

## 4. 总判定：物理学健全，缺民法

```text
站住的公理（模拟中全部兑现，方向不动摇）：
  Zone 解决空间；
  语义锚点让内容不依赖物理位置；
  enabled（作者配置）与 active（本次求值）分离；
  用户 rankKey 拥有终审权。

缺失的社会性公理：
  词汇表的所有权；
  沉默时的缺省判决；
  意图冲突的让位规则；
  公地（上下文预算）的分配。
```

社会性公理缺席时，物理学会被磨成武器：hint 军备竞赛用的正是排序机制，词汇分裂用的正是"骨架可自定义锚点"的自由。

结论：**这套哲学适合多方贡献，且是对该问题最认真的骨架——前提是补上多方公理层，而其大头（求值语义附录 + 缺省判决表两份短文档）成本不高。**

## 5. 收束一：官方词汇表 = 标准区清单 + 参考骨架

### 5.1 标准化的是接口名，不是版式

```text
区的布局（谁上谁下）：预设作者的私产，可自由重排。
区的名字（接口）：公共协议，任何骨架下必须可解析。
```

官方维护一份**分类法（标准区清单）+ 参考实现（默认骨架及建议顺序）**。生态在参考骨架上生长；预设作者做的是"重排版"，不是"发明新词汇"。内容作者锚定标准名，换预设不搬家的机制保障就一条：**标准名永远可解析**（预设可重排、可显式声明不支持，但不得静默丢失）。

潜规则与词汇表互补：ST 生态中"卡作者不碰预设顶部身份设定"的秩序真实存在，但潜规则防的是故意越界，防不了词汇分裂（模拟中 `char.persona` 失配并非恶意，是方言差异）。**词汇表给潜规则提供附着物**——"不要碰 `system.core`"成立的前提是大家都管它叫 `system.core`。

### 5.2 分类学吸收冲突

```text
ST depth 内卷的根源：只有一个坐标系（距末尾的消息数），
所有异质内容被迫在同一根数轴上比数字。

Loom 的解法：先归类、再排类。
冲突从"我数字比你大"变成"你属于哪一类"，
而类的顺序是结构决策（预设 / 用户的权力），
不是内容作者军备竞赛的对象。
```

由此**否决"意图强度声明"方案**（must-last / prefer-late 等）：强度本质仍是数字，只是换皮的 depth，迟早重新内卷。类内若确有多元成员，顺序影响小，用户 rankKey 终审兜底。

### 5.3 两块兵家必争之地，治理工具不同

**最底部（tail）**：争的是物理资源——近因注意力。最贵的地皮最不该留成用数字抢的荒野，解法是显式分带（"城市规划"）。按 ST 生态的实际沉积层，候选序列（自上而下，内部顺序待议）：

```text
tail.context   想吃近因红利的设定 / 世界观
tail.behavior  行为矫正 / 一致性守则
tail.format    输出格式要求（ST 生态事实上的最底层惯例）
tail.event     runtime 一次性事件（最贴用户输入）
```

"我要靠底"从数字竞赛变成分类申报；模拟中 9999 > 9000 > 0 的闹剧随之消失——异类内容本就不该在同一格子里比数字。

**设定层**：争的表面是位置，实质是预算（公地）与事实权威（语义冲突）。分类学解不了，工具是另一套：来源块隔离（防挤压）、可牺牲性声明 + 裁剪进 trace（防公地悲剧）、冲突可见性（平台不裁决对错，但让矛盾呈现给用户）。

### 5.4 标准区的社会形态标注

每个标准区标注期望的贡献者形态，治理预算按形态分配：

```text
单一权威区（system.core）：
  基本只有预设写；潜规则 + accepts 即可，几乎不需要 resolution。

少数协作区（style.guide、tail.behavior）：
  预设为主、卡偶尔补充。

开放公用区（setting.stable、tail.context、chat.inside）：
  多方汇流，治理投入集中于此。
```

## 6. 收束二："区 / 块 / 条"三层结构

### 6.1 Zone 与 Injection Group 合并

原设计是三层间接：内容声明 group → group 映射到 (zone, anchor) → zone 排版。收束为一层：

```text
区（Zone）：
  既是排序分类，又是声明式接口名，又是显示单位。
  区的名字就是接口，区的顺序就是排版。
  所见即契约。
```

原间接层承担的职责去向：

- **anchor（before / inside / after）**：由"相邻的独立区"取代（`chat.before` 就是排在聊天区前的一个区）；
- **多对一映射**：随 anchor 消解，不再需要；
- **band 语义**（缓存稳定性 / 近因红利）：保留为区的元数据属性；
- **失败哲学**：不变——未知区名的缺省判决仍是待决问题（§7）。

标准词汇表随之简化为**标准区清单**；tail 分带四区即清单中的四行。

### 6.2 预设不需要资源树：所见即骨架

预设天生是排序制品，作者本就在 prompt 顺序里思考。给预设配按主题分类的文件夹树属过度设计：

```text
预设：没有自己的资源树，骨架即组织。
  条目直接住在区里；禁用的就地灰掉；
  变体（保守 / 冒险开关）即同区兄弟原子 + 启用开关。

外部资产：有自己的存储组织（世界书的地理 / 人物 / 器物目录树），
  但那属于资产自己的编辑器；
  进入预设层的唯一形态是"区里的来源块"。
```

原"Source Tree 与 Zone Tree 分离"原则收窄为上述更干净的版本。

### 6.3 来源块：出处即协议

```text
预设层（Prompt 视图 = 骨架本体）
│
├── 区 …………… 排序分类 + 接口名 + 显示单位
│     ├── 原生条目 … 预设作者自己写的，裸放，无包装
│     └── 来源块 …… 外部内容的唯一进入形态
│           衣服世界书@setting.stable   （10 条静态设定成一块）
│           衣服世界书@setting.dynamic  （20 条季节条目在另一区另成一块）
│           命运骰@tail.event           （哪怕单条也成块）
```

来源块即 source-scoped dynamic slot 的具名化，并补足其第二重语义：**块不只是防挤压的排序单位，更是出处声明**。外部内容永远带块、原生内容永远裸放——这个不对称本身就是协议：Prompt 视图一眼可见"哪些是预设本体、哪些是外人注入、来自谁"。模拟中"人设沉底、用户在世界书身上找错"的可解释性问题被此不对称天然解掉一半。

一本外部资产可在多个区各成一块，各块独立排序；块内条目顺序由来源声明 + 用户微调决定。

## 7. 开放决定

1. **嵌套深度**：建议锁死"顶层区扁平有序；区内两层（裸条目，或来源块 → 条目）；来源块内不得再嵌块"。
2. **卫星依附**：区是否需要可选的"依附于某区"声明（挪动主区时卫星跟随）？倾向 v0 不做，靠标准清单默认邻接兜底。
3. **单条块显示**：仅一条的来源块渲染为轻量徽标形态，避免 Prompt 视图破碎。属 UI 约定，应写入词汇表文档防实现漂移。
4. **失败哲学缺省**：未知区名 / 悬空 fact 的缺省是降级进 fallback（宽容）、隔离并警告（保守）、还是硬错误（严格）？此缺省决定生态的容错文化。
5. **tail 分带内部顺序**：格式要求与行为矫正谁更靠底等，答案将固化为生态的"宪法惯例"。
6. **设定层预算最小公理**：可牺牲性声明 + 裁剪进 trace，何时引入、字段形态。
7. **两份短文档**：求值语义附录（§3.3 上层）与缺省判决表（§3.3 下层）的起草。
