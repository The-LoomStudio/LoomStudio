# 前端 CDP 深度专审准备：Network 与 Performance

日期：2026-11-04。

状态：方法参考；本轮报告及两项修复已[归档](../../archive/issues/frontend-cdp-deep-audit-2026-11-04.md)。本文保留取证范围，不代表所有方向已覆盖，也不构成继续施工授权。

## 目标与已有覆盖

在已有 [CDP 实战指南](../../guide/frontend-cdp-diagnostics.md)基础上，补齐请求瀑布、DevTools 请求详情、主线程火焰图与渲染流水线的关联取证。已有审查包含 Network 事件、对象生命周期、调用计数与取消实验，不能笼统认定之前只看了 Console；本轮重点是这些局部证据尚不能回答的整条交互耗时。

先与[既有审计报告](../../archive/issues/frontend-cdp-investigation-2026-11-04.md)、[修复计划](../../archive/plans/frontend-cdp-remediation-2026-11-04.md)和[后续事项](../issues/audit-follow-ups.md)去重。历史缺陷重新核实，真实环境延期项不因新增专审自动恢复执行。

## 工具与现场

先读取当前 browser-diagnostics 技能与浏览器工具文档，接入现有页面，核对实际服务、构建、HEAD、相关工作区改动和页面数据规模。分别记录 CDP Network、Tracing、Profiler、Worker target 与原生 DevTools 界面是否可用；不预设协议支持，也不为此另开调试端口或扩大权限。

- CDP 用于有界事件采集、身份配对和精确读数；Console 用于必要的局部状态确认。
- Computer Use 用于直接操作 DevTools Network / Performance，查看请求详情、Initiator 链、选中时间段、火焰图、Bottom-up 与 Call tree。不能只用 Console 计数替代这部分，也不为了展示工具而逐条手抄请求。
- CDP 无法录制 trace、但 DevTools 可用时，使用界面录制；两者均受限时，明确未覆盖项，不拿 Performance API 总时长冒充 CPU profile。
- DevTools 停靠会改变 viewport 与虚拟列表规模，录制本身也有开销。固定布局并记录；必要时非停靠取证。不同条件的数据不能直接比较。

## 专审顺序与证据

| 顺序 | 场景与问题 | 必须取得的证据 |
| --- | --- | --- |
| 1. Network 深查 | 页面启动、首次打开资源工作台或历史列表：慢在串行依赖、等待连接、服务器响应还是正文下载？ | 有界瀑布；相关请求的 Timing、Initiator、协议、连接复用、优先级、传输量与缓存来源；关联实际 UI 可用时点 |
| 2. Performance 火焰图 | 选择上一步最明显的等待，或有证据的输入/面板切换卡顿：主线程在做什么？ | 一次动作的时间线、Main 线程调用栈、Bottom-up 的 self/total time、长任务及相关源码所有者；区分脚本、样式计算、布局、绘制、GC |
| 3. 渲染与阅读 | 现有消息展开、滚动、iframe 高度变化：是否反复测量或整片更新？ | 对应帧与布局/绘制事件、触发栈和实际 DOM 规模；仅对具体疑点启用渲染辅助视图，并在结束后关闭 |
| 4. 后台与生命周期 | 关闭重型面板、切换对象后：是否仍持续请求、计算或保留资源？ | 同等时长的可见/关闭后窗口；请求与周期任务来源、相关 Worker 活动；有增长疑点才做定向分配或保留链取证 |

先完成 1、2 的一条完整链，再按发现进入 3、4，不要求扫描全站或凑够问题数。交互优先使用现有只读路径，不发送真实模型请求，不新建或修改业务数据。需要业务写入、刷新未确认保存的原页或扩大故障注入范围时，单独说明影响并遵守当前授权。

每条链分别记录动作、数据规模、起止标记、请求身份、响应完成、JS 工作和 UI 可用时点。Network 与 trace 时间轴须核对时间基准，不能直接相减不同 clock 的时间戳。选中同一动作窗口阅读火焰图，避免把空闲、加载与别的交互一起归因。

## 对照与误判边界

- 先录正常基线；只有明确假设需要时才关闭缓存、限速、CPU throttling 或拦截请求，记录参数并恢复。普通刷新、暖缓存与严格冷启动分别报告。
- TTFB 不是后端 CPU 时间；Stalled 不是确定的连接池瓶颈；响应结束后的等待也不能只凭时间顺序归因 React。
- Bottom-up 的 total time 包含子调用，不能与 self time 混加；采样 CPU profile 不等于完整浏览器 trace。React commit 数、DOM mutation 数与帧数也不能互换。
- 开发构建、HMR、扩展、录制和诊断探针可能影响结果。没有生产构建对照时，只报告当前环境；不将单次最慢样本外推普遍体验。仅在波动影响判断时复测。
- 资源传输、解压、解析、React 更新、布局和绘制分别归因；没有相应事件/调用栈时保留缺口。Worker 不在 Main 火焰图内不等于没有计算。
- 不默认导出 HAR、trace、堆快照或截图集合。需要保留时先确认工具能力、敏感内容与存放范围；不暴露凭据、正文、请求参数或本地私有路径。报告保留脱敏的相关栈、指标与证据定位。

## 输出与完成标准

本轮正式结果已归档至 `docs/archive/issues/frontend-cdp-deep-audit-2026-11-04.md`；后续新审查按当前范围建立报告，不复用已冻结的施工入口。沿用[审计流程](../../guide/audit-workflow.md)的发现字段，已确认问题、候选、反证和未覆盖项分开记录，重复根因回链原问题。

完成至少一条 Network → 主线程/渲染 → UI 可用的关联链；记录实际使用的 DevTools 视图、选中时间窗口、关键读数与源码归属。工具限制导致无法完成时明确报告阻塞，不能标记专项通过。没有成立问题也可以收口，不自动优化或建设性能测试体系。

结束时恢复限速、缓存设置、渲染辅助和所有临时探针，停止录制、释放调试引用，关闭自建页，保留用户原页。新增且已验证的方法回写 CDP 实战指南；本准备文档中的待执行方法不能提前登记为实测经验。
